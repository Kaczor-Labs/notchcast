# System Tools

A Notchcast add-on (`Tinycast/Features/Notchcast/SystemTools/`) behind one switch, **System tools** in Settings › Notchcast › Mac Tweaks, off by default. While it is on it offers five launcher commands, **Kill Process**, **Test Network Quality**, **Copy Wi-Fi Password**, **Copy Local IP Address** and **Copy Public IP Address**, and a **Touch ID for sudo** switch under it.

## Invariants

- **Touch ID for sudo writes only `/etc/pam.d/sudo_local`**, which `/etc/pam.d/sudo` includes and macOS keeps across updates. `SudoTouchIDPolicy.change` is the only edit: a pure text transform that appends `auth sufficient pam_tid.so` or removes those lines, keeps every other line byte for byte, and returns nil when the file already says what was asked, so nothing is written and nothing prompts. Only a line whose words are exactly `auth sufficient pam_tid.so`, with no option or comment after, is the switch's own, since On writes it back the same; any other active line naming `pam_tid.so` means it was set up by hand: the switch shows on, disabled, with a line saying so, and `change` returns nil both ways. The switch shows the file, read on appear and after every write, never a stored preference. An existing file that cannot be read is never rewritten.
- **One privileged route, asked every time.** `SudoTouchIDFiles.live` runs a fresh `/usr/bin/osascript` with `do shell script … with administrator privileges`, so macOS shows its own admin prompt for each change and no grant carries over. The new text travels as an argument, is staged root-owned and `0444` next to the target, then moved over it. No helper tool, no stored credential, no entitlement. A declined prompt (AppleScript `-128`) changes nothing and reports nothing.
- **Kill Process lists only the user's own processes**, never Notchcast (this copy or another), pid 1, `loginwindow`, `WindowServer`, `launchd` or `kernel_task`, by name or by path (`ProcessListPolicy.isProtected`). A signal first matches pid and start time again, so a pid the system handed on is left alone. Regular apps quit through `NSRunningApplication` (`terminate`, `forceTerminate`), other processes through `SIGTERM` and `SIGKILL`; a process already gone counts as quit. Nothing escalates to admin rights.
- **Kill Process and local addresses are adapted from Vorssaint** (GPL-3.0-or-later): `Model/ProcessListPolicy.swift`, `Model/NetworkAddressPolicy.swift`, `Service/LiveProcesses.swift` and `Service/LiveNetworkAddresses.swift` keep its notice and are listed in `notchcast/licenses/borrowed/SystemTools.txt`.
- **Force Quit asks first**, through `DialogController` via `context.confirmDestructive`; a context without it, as in harnesses, answers no.
- **One network test at a time**, `/usr/bin/networkQuality -c`, its progress and result on the island as notices (`systemTools.network`), no new island page. Esc (an observing key tap that exists only while the test runs, live only with Accessibility) or a click on the progress notice cancels and ends the tool. Every run ends with a notice: the result, Network Test Failed, or Network Test Cancelled.
- **Copy Wi-Fi Password copies the current network's password at once.** macOS 26 hides the current network's name from an app without Location Services, so the command needs Location access, used only to read that name (`CWWiFiClient.shared().interface()?.ssid()`): no position is ever requested. macOS's Location prompt appears the first time the command runs while the access is undecided (`WiFiLocationAccess`), never at launch. With Location off, or with no current network, the command opens the picker of saved networks (`networksetup -listpreferredwirelessnetworks`); with Location off its header says so. This costs three upstream files: the two usage strings in `Tinycast/Info.plist`, and `com.apple.security.personal-information.location` in `Tinycast.entitlements` and `TinycastCloud.entitlements`, without which the hardened runtime refuses the prompt.
- **Every copy calls `context.prepareClipboardMutation()` first**, so the user's last copy reaches history before it is overwritten; no copy calls `synchronizeClipboard`, so the addresses enter history like any stock copy, and the password stays out through the concealed type.
- **A Wi-Fi password is read through macOS's own prompt.** It comes from `security find-generic-password -D "AirPort network password" -a <network> -w /Library/Keychains/System.keychain`, the System keychain only, so macOS asks each time unless the user chose Always Allow in its prompt. The secret is read from the pipe only, never logged. It is copied concealed (`org.nspasteboard.ConcealedType`) so clipboard history skips it, and shown on the island for 8 s.
- **The public IP is the add-on's one request**, sent only when the command runs: `https://api.ipify.org` on a private `.ephemeral` session with `urlCache = nil`. A reply counts only when it is one bare IPv4 or IPv6 address. Local addresses come from the interface list (IPv4, up and running, no loopback, tunnels or peer links), labelled with the system's connection name.
- **Harnesses touch nothing real**: no process is read or signalled, no tool runs, and the pam files live in a scratch folder.

## How it works

| Piece | Does |
| - | - |
| `SystemToolsAddon` | The switch, the five commands and the Touch ID row. |
| `Model/ProcessListPolicy` | Which processes are offered, CPU between two readings as a share of the whole Mac (0–100), memory as physical footprint, and the order: names containing the query or the pid it spells, busiest first, ties by pid; a refresh keeps the shown order and puts new processes last. |
| `Model/NetworkAddressPolicy` | Which interfaces carry a local address, and their order. |
| `Model/NetworkInfoPolicy` | Reads `networksetup`'s Wi-Fi device and saved networks, and checks the public-IP reply. |
| `Model/SudoTouchIDPolicy` | The `sudo_local` state (off, on, set up by hand), its transform, and whether `sudo` still includes it. |
| `Model/NetworkQualityResult` | Parses `networkQuality -c` (`dl_throughput`, `ul_throughput`, `responsiveness`, `error_code`) into "↓ 278 Mbps  ↑ 21.4 Mbps  1,234 RPM". |
| `Service/LiveProcesses` | libproc readings of the user's processes and the quit itself. |
| `Service/KillProcessSession` | One open picker: readings, query, selection by pid, and the quit. Rows are sorted when the query changes and once when the first CPU figures arrive; later refreshes only update figures, so no row moves under the pointer. When the selected process is gone the picker closes with an "Already Quit" notice rather than moving the selection. |
| `Service/SystemToolsModule` | Opens the picker; runs, cancels and reports the network test. |
| `Service/SystemToolsModule+Addresses` | The address and Wi-Fi password commands: one lookup at a time, each answer shown and copied. |
| `Service/SystemToolsPicking` | What a picker lists and does; `WiFiNetworkSession` lists the saved networks. |
| `Service/WiFiLocationAccess` | The Location status and macOS's prompt for it. |
| `Service/SudoTouchIDStore` | Reads the pam files, writes through `SudoTouchIDFiles`, rereads; a file that differs from the text it asked for counts as a failed write. |
| `UI/SystemToolsPicker` | The stock `PopoverMenu` in a `MenuPanel`, centred on the pointer's display: typing filters, ↩ chooses (Kill Process: ↩ quits, ⌥↩ or ⌥-click force quits, refreshed every 2 s), Esc clears the query and then closes. |

Harnesses: `Tests/nc-SystemTools-policy-test.swift` (filtering and sorting, the pam transform, output parsing, interface rules and reply checks), `Tests/nc-SystemTools-module-test.swift` (the switch gating its commands, kill by name, rows keeping their order on refresh, the picker closing when the selected process is gone, Force Quit asking first, the network test's result, cancel and failure), `Tests/nc-SystemTools-pam-test.swift` (the Touch ID store on a scratch pam folder, a hand-written rule left alone; it runs on Linux too) and `Tests/nc-SystemTools-network-test.swift` (local and public addresses, the current network's password with Location on, the prompt while undecided, the Wi-Fi picker with Location off), sharing the fakes in `Tests/nc-SystemTools-fixture.swift`.
