# Hidden features

The one list of what Notchcast hides and how. Code stays compiled so upstream harnesses and future rebases retain their sources. `Tests/notchcast-hidden-features-test.swift` fails if a hidden tab or row returns to the Settings sidebar, Settings search or a settings link; the forced-off getters below have no harness (none compiles `AppSettings`), so a rebase keeps them by reading this page.

`NotchcastHidden` in `Tinycast/Features/Notchcast/Hidden/` owns the hidden tab set and, per tab, the English keys of hidden rows; `NotchcastIslandPins` there holds the pinned values; it needs `SettingsTab`, so `notchcast/command-harness-sources.sh` adds it to every harness that compiles `SettingsTab.swift`. `NotchcastHiddenCommands` beside it owns the hidden commands and the forced-off launcher categories (see Mechanism); the same script adds it to every harness that compiles `AppIndex.swift` or `VisibilityStore.swift`. On rebase retain the filtering hooks and forced-off getters, even if upstream adds stored defaults or backup restore paths.

- Extensions: `AppSettings.extensionsEnabled` always reads false and ignores writes, including persisted consent and backup restore. `SettingsTab` omits its sidebar row and rejects its settings slug; `SettingsSearchCatalog` omits its search entries. Upstream's `ExtensionManager` publishes no launcher entries while off; `AppCore.allowsHotKeyAction` follows the switch, so a stored binding never registers its chord. `ExtensionCoordinator` rejects store-install links as well as its existing command and link gates. With no entries, upstream's launcher, actions menu and palette accessory have nothing to act on, so they carry no gate.
- Appearance: stock colours resolve from `NSAppearance`, so Light or System would put black text on the black island. `AppSettings.appearance` always reads dark and ignores writes, persisted values, backup restore and the `settings.json` mirror; `AppCore.applyAppearance()` therefore sets `NSApp.appearance` to dark from launch.
- Dragging and snapping: `AppSettings.paletteDraggable` always reads false. Snapping and drop guides run only inside a drag session, so no drag means no snapping; there is no snapping setting of its own.
- Placement: `AppSettings.openOnCursorScreen` always reads true, the stock default, and `palettePosition(on:)` returns nil, so a stored panel position from an earlier build is never restored and the island keeps the notch.
- Language: the app is English only. `AppSettings.pinLanguage()` writes `[NotchcastHidden.language]` to `AppleLanguages` at every launch, and `AppSettings.language` reads `.english` and drops writes, so a language carried in by a settings backup or `settings.json` changes nothing and offers no relaunch; the picker row is hidden like the rows below. Upstream's catalogs and translations stay; `Notchcast.xcstrings` carries English only (`fork-strings.md`). Dictation's language is a separate setting, drawn only for a Qwen model, which Notchcast never selects; Quick Actions' Translate to goes with its hidden tab.
- Hidden rows: a hidden row ends in `.notchcastHidden()`, which renders nothing, and `NotchcastHidden.rows` drops its search entry by English key, because titles are localized. The table is per tab: a key hides a row only in the tab that lists it, so the same title stays searchable in a tab that does not list it.
- Child rows of an off feature: a stock pane's rows under its main switch hide while it is off instead of dimming, so an off feature shows its switch alone. Each gated section keeps upstream's `.settingsEnabled(…)` and adds `.notchcastHidden(!<same condition>)` on the next line; a section upstream left ungated gets the same line. Panes: Clipboard (Commands, History, Disabled Applications, Clear history), Snippets, File Search (Full Disk Access, Indexed Items, Commands, Search Scopes, Ignore Patterns), Window Management, Quicklinks, Applications (Search Scopes and the list) and System Actions (the list, through `LauncherItemsSection`), General › Hyper Key (Include Shift while Hyper Key is None), and every `FeatureSwitchSection`'s Show in launcher (`hidesLauncherToggle || !isEnabled`). Calendar's rows are left alone, since its tab is hidden. Settings search is unchanged: a hit on a hidden child opens its pane. `notchcast-hidden-features-test` counts each line, so a sync that drops one fails.
- iCloud Sync: our builds carry no iCloud entitlement, so CloudKit never starts; upstream's switch could still be turned on, and then disabled itself while on. `AppSettings.iCloudSyncEnabled` always reads false and ignores writes, so `CloudSyncCoordinator` never starts a session (backups and `settings.json` never carried it). `ICloudSyncOffMigration` clears a switch an earlier build stored. The tab leaves the sidebar, its slug and search like Extensions. Never add the iCloud entitlement to unhide it. The `icloud-sync-off` app proof fails if a stored switch reads on or the engine starts.
- Quick Actions: `AppSettings.quickActionsEnabled` always reads false and ignores writes and persisted values (backups and `settings.json` never carried it), so `QuickActionCoordinator.applyEnabled` hides the four built-in commands and lists no custom action, and `run` refuses every action: a stored chord, built-in or custom, runs nothing. `AppCore.allowsHotKeyAction` follows the switch and the hidden commands, so a stored binding, built-in or custom, registers no chord, as for Apple Shortcuts. The compact bar offers no Quick Action (`CommandID.compactBarOptions`), so it needs no filter. The tab leaves the sidebar, its slug and search like Extensions; the `hidden-settings` app proof fails if a stored or written switch reads on.
- Apple Shortcuts: `AppSettings.appleShortcutsEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `AppleShortcutCoordinator` lists no shortcut in the launcher and never runs the Shortcuts tool; `AppCore.allowsHotKeyAction` follows the switch, so a stored binding registers no chord. The tab leaves the sidebar, its slug and search like Extensions.
- Footer app menu: `RootPaletteView.appMenuButton` ends in `.notchcastHidden()`, so the footer's left side holds only the update pill (and an extension toast); the right-hand action group keeps its trailing place, since the left group already fills the leading width. Only that button opens the `.app` menu, so its entries go with it; each stays reachable elsewhere: version and About in Settings › About, Check for Updates, Settings ⌘, and Quit ⌘Q from the pill's right-click menu, and ⌘, in the palette. Check for Updates, About, Settings and Quit are launcher commands too, but only while the stored "Enable Commands" is on (see Custom Commands). Changelog has no other home and goes. `Tests/nc-Notchcast-footer-menu-hidden-test.swift` fails if the button returns.
- Open in Browser: the row a typed web address earns is listed and opens whatever "Enable Commands" and `hiddenLauncherKinds` say; only its own item key (`command:open-in-browser` in `hiddenLauncherItems`) hides it. One upstream line, in `VisibilityStore.isCategoryEnabled`. Guarded by `nc-Notchcast-web-address-test` and the `commands-hidden` app proof, which also checks it with the Commands pane hidden and Enable Commands stored off.
- Island menu: `PillMenuRow` has no Support row, so the island's secondary-click menu never shows upstream's "Support Tinycast…"; the row is fork code, so it is left out of the list instead of hidden with a modifier.
- Support: `AppSettings.supportRemindersEnabled` always reads false and ignores writes, so `SupportReminderStore` never opens the support window on its own. `command:support` is in `NotchcastHiddenCommands.commands`, so the launcher row, its hotkey and its deeplink go. About's Support section ends in `.notchcastHidden()` and `NotchcastHidden.rows[.about]` drops its search entry. The footer app menu, the menu-bar item and the island menu, upstream's other ways in, are already gone. LICENSE and NOTICE.md stay.
- Launcher › System Settings: `.systemSettings` is in `NotchcastHiddenCommands.kinds`, so no System Settings pane is listed in the launcher and no stored pane hotkey fires; `AppIndex` still scans them. The tab leaves the sidebar, its slug and search. System Actions is a different tab and stays.
- Navigation: `AppSettings.navigationEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `WindowSwitchCoordinator` and `MenuSearchCoordinator` hide Switch Windows, Switch Windows Backwards and Search Menu Items and register nothing. The tab leaves the sidebar, its slug and search. The actions menu's own search (`ActionMenuSearchTests`) is separate and stays.
- Custom Commands and the Commands pane: `AppSettings.customCommandsEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `CustomCommandCoordinator` lists no custom command, opens neither the library nor the editor and runs none (its hotkey path included); `AppCore.allowsHotKeyAction` follows the switch, so a stored binding registers no chord and swallows no key, while the stored chords and commands stay. `command:create-custom-command`, `command:search-custom-commands` and `command:run-shell-command` are in `NotchcastHiddenCommands.commands`; Run Shell Command, a fallback that ignores the switch, also leaves the fallback rows and the Fallbacks pane through one line in `FallbackCoordinator.isAvailable`. The tab leaves the sidebar, its slug and search. That pane also held the "Enable Commands" switch (`.command` launcher kind) and the item list of the commands it gates (Settings, Quit, About, Check for Updates and the other unowned commands): nothing forces or writes that kind, so the stored value decides, and with the pane gone only a backup restore or the `settings.json` mirror (`commands.builtInEnabled`) changes it. Open in Browser ignores it. Add-on commands (Script commands among them) are our own and not Custom Commands: their rows answer to their add-on's switch, so they stay in the launcher whatever Enable Commands says. The `commands-hidden` app proof checks all of this, the add-on part on the first command `NotchcastRegistry` declares, so it names no add-on (`check-addons.py`).
- Notes: `AppSettings.notesEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `NotesCoordinator` hides its three commands, loads no store and opens no window; the island menu's three Notes rows follow the switch. The three commands are also in `NotchcastHiddenCommands.commands`, so their launcher rows, hotkeys and deeplinks go, `CompactShortcutsSection` leaves them out of its picker and a stored Show Notes slot reads Off and shows nothing in the bar. A note link (`note/<name>`) asks `DeepLinkCoordinator.exists` for Show Notes first, so it reads as unknown like a hidden command's link, not turned off. The tab leaves the sidebar, its slug and search. Note files on disk stay untouched.
- AI: `AppSettings.aiEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `AIChatCoordinator` hides Quick AI and AI Chat, loads no history or presets and opens no window; the Quick AI fallback row (`FallbackCoordinator`) and Tab to Ask AI (`PaletteTabAction`) read the switch and go with it. MCP is inert: `MCPCoordinator.isActive` needs `aiEnabled`, so no server connects or runs whatever `mcpEnabled` stores. Both commands are also in `NotchcastHiddenCommands.commands`, so General › Compact Shortcuts no longer offers Quick AI and a stored Quick AI slot shows nothing in the bar. A chat link (`chat/<id>`) asks `DeepLinkCoordinator.exists` for AI Chat first, so it reads as unknown like a hidden command's link, not turned off. The hidden command filter frees any stored Quick AI or AI Chat chord. The tab leaves the sidebar, its slug and search. The provider layer stays live for Dictation's cleanup: the installed Claude and Codex tools still start while cleanup is on (`DictationExtrasCoordinator.usesInstalledAI`), and Notchcast › Dictation › Cleanup holds an AI providers row whose Manage… opens upstream's `AIProvidersPanel`, the providers sheet the AI pane hosted, so a provider can still be added and picked as the cleanup model. `DictationExtrasCoordinator` tracks `enabledInstalledProviders`, so a tool turned on in that panel starts at once; the panel's Apple Intelligence footer points at Dictation › Cleanup instead of the AI pane. Chat history on disk stays untouched. The `hidden-settings` app proof fails if a stored or written switch reads on, MCP reads active or either command reads enabled.
- Fallbacks: it has no switch, so `FallbackCoordinator.entries(for:)` returns nothing while `.fallbacks` is in `NotchcastHidden.tabs`; no "Use … with" section or its gear appears under a search, and its rows' actions menu goes with them. The tab leaves the sidebar, its slug and search. A quicklink that asks for an `{argument}` still takes a phrase from the launcher: type its alias or name, press Tab into its own argument field (`QuicklinkArgumentsAccessory`), type, press Return; that path never reads Fallbacks, and `QuicklinkCoordinatorTests` guards it. The stored order and disabled set stay untouched. The `hidden-settings` app proof checks that the Fallbacks pane is hidden and a typed query yields no rows.
- Dictation: the stock tab leaves the sidebar, its `settings/dictation` slug, search and direct Settings navigation like Calendar; nothing aliases the old slug to the new tab. Notchcast › Dictation (`notchcast-dictation`, after Keyboard & Mouse, shown with or without add-ons) draws the rows dictation needs from `NotchcastSettingsPane`: Enable Dictation with the microphone access warning and Microphone; Shortcut behavior, Shortcut, the Globe hint, the hold caption and Play sounds; the model row; then the fork's Cleanup, History and Sharing sections as they are. It reads and writes the same `AppSettings` keys and sends the same `MainAppLink` messages as the stock tab, so `settings.json`, backups and a later unhide see one set of values. Rows it leaves out keep whatever that Mac stored and are forced to nothing: Engine and Model (pinned to Parakeet Ultra by `NotchcastCore`), Language (Qwen only), Release model from memory, When finished, Insert while recording and Adapt capitalization. Insert while recording stored on keeps cleanup from running, as before. The model row takes every fact from the main app: installed, downloading with progress, or not installed from `MainAppStatus.dictationModels`, and the size on disk from `NotchcastDictationModelSizes`, which measures each installed model in the main app and travels in `NotchcastSettingsStatus.dictationModelSizes`; the Settings process's own model store is never read, as it goes stale after a download (#1519). Dictation History is owned by the hidden tab, so `NotchcastHidden.liveCommandTabs` keeps `NotchcastHiddenHotKeys.hides` from freeing its chord. No harness moves to `HIDDEN_TESTS`: every Dictation harness tests the engine, which stays. `DictationSettingsView.swift`, `SettingsAnchor.swift` and the Dictation part of `SettingsSearchCatalog.swift` hold upstream's text, so a sync that changes them applies cleanly; a change to one of the moved rows needs a look at `DictationExtras/Settings/NotchcastDictationPane.swift`.
- Still visible, as in stock: Backup and About (Advanced group), all reachable by slug and in search.
- Menu-bar items: `AppSettings.showInMenuBar` and `notesShowsInMenuBar` always read false and ignore writes, persisted values, backup restore and the `settings.json` mirror. The General and Notes menu-bar rows end in `.notchcastHidden()` and `NotchcastHidden.rows` drops their search entries. The Raycast import list filters out the `menuBarVisibility` option.
- Calendar: the tab, slug, search and direct Settings navigation are hidden, as is the Calendars row under Permissions. The four forced-off getters suppress the menu-bar item, launcher meeting rows and card, auto join and camera preview. The hidden command set suppresses all five Calendar commands from launcher, hotkeys, deeplinks and compact shortcuts. The island's live glance provides no meeting to the countdown or expansion and the pill menu omits its Calendar actions. `calendarEnabled` controls the stock Calendar feature. While Calendar is hidden, the main app starts the shared EventKit store on every launch with an existing macOS full-access grant, even when the switch is off. Day reads Today events through `NotchcastCalendar` and can open My Schedule from its event rows. Day’s own Settings endpoint reports missing calendar access. The Grant Access button under its switch asks macOS from the main app or opens Calendars privacy settings after a denial. See the [Calendar door](doors/calendar.md).
- Only the menu-bar icon is gone, not its commands: `TinycastApp`'s `.commands` still declare Settings… ⌘, and Close Window ⌘Q on a scene that is never inserted. Quit and Settings stay reachable from the pill's right-click menu (which also takes ⌘, and ⌘Q), and from the launcher while Enable Commands is on.

## Mechanism

Four tables in our own files, each read by a short hook in upstream's; hiding a feature fills a table and touches no upstream line.

| What | Table (our file) | Upstream hook | Reaches |
| --- | --- | --- | --- |
| A Settings tab | `NotchcastHidden.tabs` | `SettingsTab.init(slug:)` and `SettingsSection.tabs`, one filter each; `SettingsSearchCatalog.entries`, one `.filter` | sidebar, `settings/<slug>` links, Settings search |
| A Settings row | `NotchcastHidden.rows[tab]`, English keys | the same `.filter` in `SettingsSearchCatalog.entries`; the row's own `.notchcastHidden()` in its pane | Settings search, the pane |
| A command | `NotchcastHiddenCommands.commands`, `CommandID`s | `AppIndex.visibleCatalogEntries` and `AppIndex.isCommandEnabled`, one added `&&` line each; `FallbackCoordinator.isAvailable`, one added `guard` | launcher, compact bar, hotkeys and deeplinks (`AppCore.allowsHotKeyAction` asks `isCommandEnabled`; `DeepLinkCoordinator.exists` answers a hidden command's link as unknown), built-in fallback rows and the Fallbacks pane |
| A launcher category | `NotchcastHiddenCommands.kinds`, `AppEntry.Kind`s | `VisibilityStore.isKindEnabled`, one added `&&` line | launcher rows of the kind, and the hotkeys `allowsHotKey` gates by kind (apps, system settings, system actions, unowned commands) |

- `NotchcastHiddenCommands.commands` holds raw `CommandID` strings, because harnesses compile it beside a stub `CommandID`; a stub without the case simply drops it. The compact bar's Settings picker (`CompactShortcutsSection`) also reads `commands`, so a hidden command is never offered as a shortcut.
- A forced category reads off whatever `hiddenLauncherKinds` stores, and forcing writes nothing: the stored value and backups (which copy the stored set) keep what the user chose, and it returns when the force is lifted. The opt-in `settings.json` mirror asks `isKindEnabled`, so it shows a forced kind as off. A kind can only be forced off; nothing can force one on. The stored "Enable Commands" value is the owner's and stays off: never write it. `setKindEnabled(true, …)` on a forced kind still clears the stored value, so hide the kind's Settings switch with it.
- A forced category does not reach an entry a feature pane owns (`settingsOwner`), nor Open in Browser: `VisibilityStore.isCategoryEnabled` lets those through, as in stock. Hide such a command by `CommandID`.
- The hidden commands are read when `AppIndex` publishes; the set is a build-time constant, so nothing republishes for it.
- A chord a hidden feature stored before its hide owns nothing: `NotchcastHiddenHotKeys.hides` names the actions of a hidden tab (Apple Shortcuts, Extensions, Quick Actions, Navigation, Commands with each Custom Command), a forced-off System Settings pane and a hidden command, and `HotKeyManager.isHidden` (set in `AppCore`'s init) drops them from its candidates, so the recorder, a backup or `settings.json` can take that chord with no conflict naming a feature with no screen. A hidden command's or pane's chord stays only in stored defaults. Settings backups and `settings.json` omit it. At launch after a hide is lifted, a previously hidden binding returns unless another live binding now conflicts with it. In that case the other action keeps its chord and only the returning binding is removed from defaults. The `hidden-hotkeys` app proof fails if `AppCore.allowsHotKeyAction` lets a forced-off feature's chord through or the shipped wiring stops freeing them.
- Neither table reaches a caller that skips `AppIndex` (built-in fallbacks aside, above): quicklink fallback rows, the island pill menu, About's buttons and the launcher's Tab to Ask AI call their coordinators directly. Hiding a feature that has such a caller needs that feature's own switch forced off, or one more hook.
- `var`, not `let`, only so a harness can fill them: `nc-Notchcast-command-alias-test` (a hidden command leaves the index and reads disabled), `nc-Notchcast-web-address-test` (a forced kind reads off after `setKindEnabled(true, …)`, stored kinds untouched, Open in Browser still offered) and `notchcast-hidden-features-test` (a row hidden in one tab only).

## Harnesses

`HIDDEN_TESTS` in `notchcast/config.env` lists the upstream harnesses whose whole subject is a hidden item. `notchcast/test-harnesses.sh` drops them from every whole-suite run (PR and Main harnesses CI, Sync, `land.sh`, local `./Scripts/run-tests.sh`) and `notchcast/changed-harnesses.sh` never selects them; naming one still runs it (`./Scripts/run-tests.sh ExtensionTests`). The files stay in `Tests/` and in upstream's `Scripts/run-tests.sh`, so sync is untouched. A harness that also covers visible code (`CalendarTests`, `PalettePlacementTests`, `AppearanceTests`, `InterfaceSizeTests`, `CustomCommandTests`, the only harness of `Tinycast/Platform/PseudoTerminal.swift`, which the Script Commands add-on runs, and `LanguageTests`, which guards the English plurals, labels and app-name override) keeps running.

- Extensions: `ExtensionTests` (with `ExtensionFetchTests` and `ExtensionTests+MenuBar` compiled into it), `ExtensionAccessoryTests`, `ExtensionCleanupTests`, `ExtensionFormTests` (with `ExtensionListKeyTests`), `ExtensionIconTests`, `ExtensionImageSizeTests`, `ExtensionMetadataTests`, `ExtensionRefreshTests`, `ExtensionSignInTests`, `ExtensionStoreTests`, `ExtensionVersionTests`, and `SymbolsTests` (the SF Symbol catalog only the extension appearance picker reads).
- Apple Shortcuts: `AppleShortcutTests`.
- iCloud Sync: `CloudSyncTests`.
- Support: `SupportTests`.
- Navigation: `WindowSwitchTests`, `MenuSearchTests`.
- Quick Actions: `QuickActionTests` and `TextDiffTests` (the result panel's diff engine; `TextDiffPerformanceTests` is index-only upstream and never runs). `CompactBarTests`, `HotKeyTests`, `DeepLinkTests` and `LauncherSettingsFileTests` keep running: they compile Quick Actions model files only as dependencies.
- Custom Commands: `CustomCommandListTests`.
- Notes: `NotesTests`, `NotesEditorTests` (`NotesEditorPerformanceTests` is index-only upstream and never runs).
- AI: `AIChatTests`, `ChatMarkdownTests`, `SyntaxHighlightTests`, `MCPTests`, `MCPOAuthTests`, `MCPStdioTests`, `OpenCodeMCPTests`. The provider tier (`AIProviderTests`, `AIResponsesTests`, `AppleIntelligenceTests`) keeps running, since Dictation's cleanup calls it; so do `DictationFieldTests` (it compiles the chat composer only as a dependency) and `PaletteTabTests`.
- Fallbacks: `FallbackTests`. `QuicklinkTests` and `QuicklinkCoordinatorTests` keep running.

No CI step serves only a hidden item: CodeQL's JavaScript scan skips the Raycast runtime (`Scripts/raycast-runtime/`, `Tinycast/Resources/RaycastRuntime.generated.js`, `Tests/ext-fixtures/`), the Generated workflow sets up no Node and never rebuilds that runtime (it stays upstream's).

Kept on purpose: everything that guards the hiding (`notchcast-hidden-features-test`, `nc-Notchcast-footer-menu-hidden-test`, `notchcast-icloud-sync-off-migration-test`, the `hidden-settings`, `hidden-hotkeys`, `commands-hidden` and `icloud-sync-off` app proofs); harnesses that only compile a hidden model as a dependency of a visible one (`DeepLinkTests`, `InterfaceSizeTests`, the `$SYNC` sources in `SnippetsTests`) and `RaycastTests` (the visible Raycast import); Light-appearance checks inside visible harnesses (`nc-NotchLook-tokens-test`, `nc-Island-keyline-test`, `nc-Notchcast-island-cards-test`) and the DEBUG `keyline` scene, which run with the visible code they sit in and run on no CI runner (scenes) or cost no measurable time; upstream's `Scripts/check-localizations.js` in `Scripts/lint.sh` (0.15 s; dropping it means patching upstream's lint script); and the Debug build, which still compiles hidden code so a rebase keeps it.

When you hide an item, add the harnesses that test only it; when you unhide one, remove them.

Excluded harnesses are not compiled in our runs, so un-hiding a feature means fixing its harnesses first.
