# Hidden features

The one list of what Notchcast hides and how. Code stays compiled so upstream harnesses and future rebases retain their sources. `Tests/notchcast-hidden-features-test.swift` fails if a hidden tab or row returns to the Settings sidebar, Settings search or a settings link; the forced-off getters below have no harness (none compiles `AppSettings`), so a rebase keeps them by reading this page.

| State | Item | Tab slug | Command IDs | Forced off | Hooks |
| --- | --- | --- | --- | --- | --- |
| Hidden | Extensions | extensions | none | extensionsEnabled | AppSettings, settings tab and search, extension coordinator, hotkeys |
| Hidden | Apple Shortcuts | apple-shortcuts | none | appleShortcutsEnabled | AppSettings, settings tab and search, hotkeys; the coordinator's existing gates |
| Hidden | Appearance picker | general (row) | none | appearance, pinned to dark | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Launcher dragging and snapping | general (row) | none | paletteDraggable | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Launcher placement | general (row) | none | openOnCursorScreen, stored panel positions | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Menu-bar icon | general (row) | none | showInMenuBar | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Notes menu-bar item | notes (row) | none | notesShowsInMenuBar | AppSettings, NotesSettingsView, SettingsSearchCatalog |
| Hidden | Calendar menu-bar item and its four rows | calendar (rows) | none | calendarMenuBarDisplay (disabled) | AppSettings, CalendarSettingsView, SettingsSearchCatalog |
| Hidden | Raycast import "Menu-bar icon" checkbox | none | none | none (the option imports into a no-op) | RaycastImportSelection |
| Hidden | Launcher footer app-menu button and its menu | none | none | none (`appMenuButton` renders nothing) | RootPaletteView |
| Hidden | Language picker | general (row) | none | AppleLanguages, pinned to English at launch | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | iCloud Sync | icloud-sync | none | iCloudSyncEnabled | AppSettings, settings tab and search, `ICloudSyncOffMigration` at launch |
| Hidden | Support | about (row) | command:support | supportRemindersEnabled | AppSettings, AboutView, SettingsSearchCatalog, `NotchcastHiddenCommands.commands` |
| Hidden | Launcher › System Settings | system-settings | none | launcher kind systemSettings | settings tab and search, `NotchcastHiddenCommands.kinds` |
| Hidden | Navigation (Switch Windows, Search Menu Items) | navigation | none | navigationEnabled | AppSettings, settings tab and search |
| Hidden | Quick Actions | quick-actions | fix-grammar, rewrite, translate, summarize (via the switch) | quickActionsEnabled | AppSettings, settings tab and search; the coordinator's existing gates |
| Hidden | Custom Commands, Run Shell Command and the Commands pane | commands | command:create-custom-command, command:search-custom-commands, command:run-shell-command | customCommandsEnabled | AppSettings, settings tab and search, `NotchcastHiddenCommands.commands`, `FallbackCoordinator.isAvailable`, HotKeyManager |

`NotchcastHidden` in `Tinycast/Features/Notchcast/Hidden/` owns the hidden tab set and, per tab, the English keys of hidden rows; `NotchcastIslandPins` there holds the pinned values; it needs `SettingsTab`, so `notchcast/command-harness-sources.sh` adds it to every harness that compiles `SettingsTab.swift`. `NotchcastHiddenCommands` beside it owns the hidden commands and the forced-off launcher categories (see Mechanism); the same script adds it to every harness that compiles `AppIndex.swift` or `VisibilityStore.swift`. On rebase retain the filtering hooks and forced-off getters, even if upstream adds stored defaults or backup restore paths.

- Extensions: `AppSettings.extensionsEnabled` always reads false and ignores writes, including persisted consent and backup restore. `SettingsTab` omits its sidebar row and rejects its settings slug; `SettingsSearchCatalog` omits its search entries. Upstream's `ExtensionManager` publishes no launcher entries while off; `HotKeyManager` exposes no bound extension commands, so a stored binding never registers its chord. `ExtensionCoordinator` rejects store-install links as well as its existing command and link gates. With no entries, upstream's launcher, actions menu and palette accessory have nothing to act on, so they carry no gate.
- Appearance: stock colours resolve from `NSAppearance`, so Light or System would put black text on the black island. `AppSettings.appearance` always reads dark and ignores writes, persisted values, backup restore and the `settings.json` mirror; `AppCore.applyAppearance()` therefore sets `NSApp.appearance` to dark from launch.
- Dragging and snapping: `AppSettings.paletteDraggable` always reads false. Snapping and drop guides run only inside a drag session, so no drag means no snapping; there is no snapping setting of its own.
- Placement: `AppSettings.openOnCursorScreen` always reads true, the stock default, and `palettePosition(on:)` returns nil, so a stored panel position from an earlier build is never restored and the island keeps the notch.
- Language: the app is English only. `AppSettings.pinLanguage()` writes `[NotchcastHidden.language]` to `AppleLanguages` at every launch, and `AppSettings.language` reads `.english` and drops writes, so a language carried in by a settings backup or `settings.json` changes nothing and offers no relaunch; the picker row is hidden like the rows below. Upstream's catalogs and translations stay; `Notchcast.xcstrings` carries English only (`fork-strings.md`). Dictation's language is a separate setting and stays; Quick Actions' Translate to goes with its hidden tab.
- Hidden rows: a hidden row ends in `.notchcastHidden()`, which renders nothing, and `NotchcastHidden.rows` drops its search entry by English key, because titles are localized. The table is per tab: a key hides a row only in the tab that lists it, so Dictation's own Language row stays searchable while General's is gone.
- iCloud Sync (#910): our builds carry no iCloud entitlement, so CloudKit never starts; upstream's switch could still be turned on, and then disabled itself while on. `AppSettings.iCloudSyncEnabled` always reads false and ignores writes, so `CloudSyncCoordinator` never starts a session (backups and `settings.json` never carried it). `ICloudSyncOffMigration` clears a switch an earlier build stored. The tab leaves the sidebar, its slug and search like Extensions. Never add the iCloud entitlement to unhide it. The `icloud-sync-off` app proof fails if a stored switch reads on or the engine starts.
- Quick Actions (#1218): `AppSettings.quickActionsEnabled` always reads false and ignores writes and persisted values (backups and `settings.json` never carried it), so `QuickActionCoordinator.applyEnabled` hides the four built-in commands and lists no custom action, and `run` refuses every action: a stored chord, built-in or custom, runs nothing. `HotKeyManager.boundQuickActionIDs` is empty, so a stored custom-action binding registers no chord, as for Apple Shortcuts; a binding on one of the four built-in commands stays registered and runs nothing. The compact bar offers no Quick Action (`CommandID.compactBarOptions`), so it needs no filter. The tab leaves the sidebar, its slug and search like Extensions; the `hidden-settings` app proof fails if a stored or written switch reads on.
- Apple Shortcuts: `AppSettings.appleShortcutsEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `AppleShortcutCoordinator` lists no shortcut in the launcher and never runs the Shortcuts tool; `HotKeyManager.boundAppleShortcutIDs` is empty, so a stored binding registers no chord. The tab leaves the sidebar, its slug and search like Extensions.
- Footer app menu (#882): `RootPaletteView.appMenuButton` ends in `.notchcastHidden()`, so the footer's left side holds only the update pill (and an extension toast); the right-hand action group keeps its trailing place, since the left group already fills the leading width. Only that button opens the `.app` menu, so its entries go with it; each stays reachable elsewhere: version and About in Settings › About, Check for Updates, Settings ⌘, and Quit ⌘Q from the pill's right-click menu, and ⌘, in the palette. Check for Updates, About, Settings and Quit are launcher commands too, but only while the stored "Enable Commands" is on (see Custom Commands). Changelog has no other home and goes. `Tests/nc-Notchcast-footer-menu-hidden-test.swift` fails if the button returns.
- Open in Browser (#1066): the row a typed web address earns is listed and opens whatever "Enable Commands" and `hiddenLauncherKinds` say; only its own item key (`command:open-in-browser` in `hiddenLauncherItems`) hides it. One upstream line, in `VisibilityStore.isCategoryEnabled`. Guarded by `nc-Notchcast-web-address-test` and the `commands-hidden` app proof, which also checks it with the Commands pane hidden and Enable Commands stored off.
- Island menu (#1029): `PillMenuRow` has no Support row, so the island's secondary-click menu never shows upstream's "Support Tinycast…"; the row is fork code, so it is left out of the list instead of hidden with a modifier.
- Support (#1217): `AppSettings.supportRemindersEnabled` always reads false and ignores writes, so `SupportReminderStore` never opens the support window on its own. `command:support` is in `NotchcastHiddenCommands.commands`, so the launcher row, its hotkey and its deeplink go. About's Support section ends in `.notchcastHidden()` and `NotchcastHidden.rows[.about]` drops its search entry. The footer app menu, the menu-bar item and the island menu, upstream's other ways in, are already gone. LICENSE and NOTICE.md stay.
- Launcher › System Settings (#1217): `.systemSettings` is in `NotchcastHiddenCommands.kinds`, so no System Settings pane is listed in the launcher and no stored pane hotkey fires; `AppIndex` still scans them. The tab leaves the sidebar, its slug and search. System Actions is a different tab and stays.
- Navigation (#1217): `AppSettings.navigationEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `WindowSwitchCoordinator` and `MenuSearchCoordinator` hide Switch Windows, Switch Windows Backwards and Search Menu Items and register nothing. The tab leaves the sidebar, its slug and search. The actions menu's own search (`ActionMenuSearchTests`) is separate and stays.
- Custom Commands and the Commands pane (#1219): `AppSettings.customCommandsEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `CustomCommandCoordinator` lists no custom command, opens neither the library nor the editor and runs none (its hotkey path included); `HotKeyManager.boundCustomCommandIDs` is empty, so a stored binding registers no chord and swallows no key, while the stored chords and commands stay. `command:create-custom-command`, `command:search-custom-commands` and `command:run-shell-command` are in `NotchcastHiddenCommands.commands`; Run Shell Command, a fallback that ignores the switch, also leaves the fallback rows and the Fallbacks pane through one line in `FallbackCoordinator.isAvailable`. The tab leaves the sidebar, its slug and search. That pane also held the "Enable Commands" switch (`.command` launcher kind) and the item list of the commands it gates (Settings, Quit, About, Check for Updates and the other unowned commands): nothing forces or writes that kind, so the stored value decides, and with the pane gone only a backup restore or the `settings.json` mirror (`commands.builtInEnabled`) changes it. Open in Browser ignores it (#1066). Add-on commands (Script commands among them) are our own and not Custom Commands: their rows answer to their add-on's switch, so they stay in the launcher whatever Enable Commands says. The `commands-hidden` app proof checks all of this, the add-on part on the first command `NotchcastRegistry` declares, so it names no add-on (`check-addons.py`).
- Still visible, as in stock: Backup and About (Advanced group), all reachable by slug and in search.
- Menu-bar items: the island replaces all three. `AppSettings.showInMenuBar` and `notesShowsInMenuBar` always read false and `calendarMenuBarDisplay` always reads `.disabled`, all ignoring writes, persisted values, backup restore and the `settings.json` mirror, so `TinycastApp` inserts neither `MenuBarExtra` and `NotesCoordinator` creates no status item. Their key mappings stay. The seven rows end in `.notchcastHidden()` and `NotchcastHidden.rows` drops their search entries; the Raycast import list filters out the `menuBarVisibility` option.
- Calendar › Days to Show stays visible: `calendarSpan` narrows the EventKit fetch for My Schedule and launcher search too. Its section is titled "My Schedule".
- Only the menu-bar icon is gone, not its commands: `TinycastApp`'s `.commands` still declare Settings… ⌘, and Close Window ⌘Q on a scene that is never inserted. Quit and Settings stay reachable from the pill's right-click menu (which also takes ⌘, and ⌘Q), and from the launcher while Enable Commands is on.

## Mechanism

Four tables in our own files, each read by a short hook in upstream's; hiding a feature fills a table and touches no upstream line.

| What | Table (our file) | Upstream hook | Reaches |
| --- | --- | --- | --- |
| A Settings tab | `NotchcastHidden.tabs` | `SettingsTab.init(slug:)` and `SettingsSection.tabs`, one filter each; `SettingsSearchCatalog.entries`, one `.filter` | sidebar, `settings/<slug>` links, Settings search |
| A Settings row | `NotchcastHidden.rows[tab]`, English keys | the same `.filter` in `SettingsSearchCatalog.entries`; the row's own `.notchcastHidden()` in its pane | Settings search, the pane |
| A command | `NotchcastHiddenCommands.commands`, `CommandID`s | `AppIndex.visibleCatalogEntries` and `AppIndex.isCommandEnabled`, one added `&&` line each; `FallbackCoordinator.isAvailable`, one added `guard` | launcher, compact bar, hotkeys and deeplinks (`AppCore.allowsHotKeyAction` asks `isCommandEnabled`; `DeepLinkCoordinator.exists` answers a hidden command's link as unknown), built-in fallback rows and the Fallbacks pane |
| A launcher category | `NotchcastHiddenCommands.kinds`, `AppEntry.Kind`s | `VisibilityStore.isKindEnabled`, one added `&&` line | launcher rows of the kind, and the hotkeys `allowsHotKey` gates by kind (apps, system settings, system actions, unowned commands) |

- `NotchcastHiddenCommands.commands` holds raw `CommandID` strings, because harnesses compile it beside a stub `CommandID`; a stub without the case simply drops it. #1062 fills both tables, one item per PR.
- A forced category reads off whatever `hiddenLauncherKinds` stores, and forcing writes nothing: the stored value and backups (which copy the stored set) keep what the user chose, and it returns when the force is lifted. The opt-in `settings.json` mirror asks `isKindEnabled`, so it shows a forced kind as off. A kind can only be forced off; nothing can force one on. The stored "Enable Commands" value is the owner's and stays off: never write it. `setKindEnabled(true, …)` on a forced kind still clears the stored value, so hide the kind's Settings switch with it.
- A forced category does not reach an entry a feature pane owns (`settingsOwner`), nor Open in Browser: `VisibilityStore.isCategoryEnabled` lets those through, as in stock. Hide such a command by `CommandID`.
- The hidden commands are read when `AppIndex` publishes; the set is a build-time constant, so nothing republishes for it.
- Neither table reaches a caller that skips `AppIndex` (built-in fallbacks aside, above): quicklink fallback rows, the island pill menu, About's buttons and the launcher's Tab to Ask AI call their coordinators directly. Hiding a feature that has such a caller needs that feature's own switch forced off, or one more hook.
- `var`, not `let`, only so a harness can fill them: `nc-Notchcast-command-alias-test` (a hidden command leaves the index and reads disabled), `nc-Notchcast-web-address-test` (a forced kind reads off after `setKindEnabled(true, …)`, stored kinds untouched, Open in Browser still offered) and `notchcast-hidden-features-test` (a row hidden in one tab only).

## Harnesses

`HIDDEN_TESTS` in `notchcast/config.env` lists the upstream harnesses whose whole subject is a hidden item. `notchcast/test-harnesses.sh` drops them from every whole-suite run (PR and Main harnesses CI, Sync, `land.sh`, local `./Scripts/run-tests.sh`) and `notchcast/changed-harnesses.sh` never selects them; naming one still runs it (`./Scripts/run-tests.sh ExtensionTests`). The files stay in `Tests/` and in upstream's `Scripts/run-tests.sh`, so sync is untouched. A harness that also covers visible code (`CalendarTests`, `PalettePlacementTests`, `AppearanceTests`, `InterfaceSizeTests`, and `LanguageTests`, which guards the English plurals, labels and app-name override) keeps running.

- Extensions: `ExtensionTests` (with `ExtensionFetchTests` and `ExtensionTests+MenuBar` compiled into it), `ExtensionAccessoryTests`, `ExtensionCleanupTests`, `ExtensionFormTests` (with `ExtensionListKeyTests`), `ExtensionIconTests`, `ExtensionImageSizeTests`, `ExtensionMetadataTests`, `ExtensionRefreshTests`, `ExtensionSignInTests`, `ExtensionStoreTests`, `ExtensionVersionTests`, and `SymbolsTests` (the SF Symbol catalog only the extension appearance picker reads).
- Apple Shortcuts: `AppleShortcutTests`.
- iCloud Sync: `CloudSyncTests`.
- Support: `SupportTests`.
- Navigation: `WindowSwitchTests`, `MenuSearchTests`.
- Quick Actions: `QuickActionTests` and `TextDiffTests` (the result panel's diff engine; `TextDiffPerformanceTests` is index-only upstream and never runs). `CompactBarTests`, `FallbackTests`, `HotKeyTests`, `DeepLinkTests` and `LauncherSettingsFileTests` keep running: they compile Quick Actions model files only as dependencies.
- Custom Commands: `CustomCommandTests`, `CustomCommandListTests`.

CI steps that served only a hidden item are gone too (#945): CodeQL's JavaScript scan skips the Raycast runtime (`Scripts/raycast-runtime/`, `Tinycast/Resources/RaycastRuntime.generated.js`, `Tests/ext-fixtures/`), the Generated workflow sets up no Node and never rebuilds that runtime (it stays upstream's), and `land.sh` no longer reruns harnesses when `main` moved only in it, since only `ExtensionTests` loads it. Measured on GitHub Actions: CodeQL's JavaScript job fell from 73 s (average of the 10 main runs before) to 45 and 58 s on two runs, about 20 s of a Linux runner per push to `main`, and Generated saves its Node setup, about 1 s per run; the PR and Main harness lanes already ran no hidden harness, so they are unchanged.

Kept on purpose: everything that guards the hiding (`notchcast-hidden-features-test`, `nc-Notchcast-footer-menu-hidden-test`, `notchcast-icloud-sync-off-migration-test`, the `hidden-settings`, `commands-hidden` and `icloud-sync-off` app proofs); harnesses that only compile a hidden model as a dependency of a visible one (`DeepLinkTests`, `InterfaceSizeTests`, the `$SYNC` sources in `NotesTests` and `SnippetsTests`) and `RaycastTests` (the visible Raycast import); Light-appearance checks inside visible harnesses (`nc-NotchLook-tokens-test`, `nc-Island-keyline-test`, `nc-Notchcast-island-cards-test`) and the DEBUG `keyline` scene, which run with the visible code they sit in and run on no CI runner (scenes) or cost no measurable time; upstream's `Scripts/check-localizations.js` in `Scripts/lint.sh` (0.15 s; dropping it means patching upstream's lint script); and the Debug build, which still compiles hidden code so a rebase keeps it.

When you hide an item, add the harnesses that test only it; when you unhide one, remove them.

Excluded harnesses are no longer compiled in our runs, so un-hiding a feature means fixing its harnesses first.
