# Hidden features

The one list of what Notchcast hides and how. Code stays compiled so upstream harnesses and future rebases retain their sources. `Tests/notchcast-hidden-features-test.swift` fails if a hidden tab or row returns to the Settings sidebar, Settings search or a settings link; the forced-off getters below have no harness (none compiles `AppSettings`), so a rebase keeps them by reading this page.

| State | Item | Tab slug | Command IDs | Forced off | Hooks |
| --- | --- | --- | --- | --- | --- |
| Hidden | Extensions | extensions | none | extensionsEnabled | AppSettings, settings tab and search, extension coordinator, hotkeys |
| Hidden | Apple Shortcuts | apple-shortcuts | none | appleShortcutsEnabled | AppSettings, settings tab and search, hotkeys; the coordinator's existing gates |
| Hidden | Appearance picker | general (row) | none | appearance, pinned to dark | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Launcher dragging and snapping | general (row) | none | paletteDraggable | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Launcher placement | general (row) | none | openOnCursorScreen, stored panel positions | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Menu-bar icon | general (row) | none | showInMenuBar | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | Notes menu-bar item | notes (row) | none | notesShowsInMenuBar | AppSettings, NotesSettingsView, SettingsSearchCatalog |
| Hidden | Calendar menu-bar item and its four rows | calendar (rows) | none | calendarMenuBarDisplay (disabled) | AppSettings, CalendarSettingsView, SettingsSearchCatalog |
| Hidden | Raycast import "Menu-bar icon" checkbox | none | none | none (the option imports into a no-op) | RaycastImportSelection |
| Hidden | Launcher footer app-menu button and its menu | none | none | none (`appMenuButton` renders nothing) | RootPaletteView |
| Hidden | Language picker | general (row) | none | AppleLanguages, pinned to English at launch | AppSettings, GeneralSettingsView, SettingsSearchCatalog |
| Hidden | iCloud Sync | icloud-sync | none | iCloudSyncEnabled | AppSettings, settings tab and search, `ICloudSyncOffMigration` at launch |

`NotchcastHidden` in `Tinycast/Features/Notchcast/Hidden/` owns the hidden tab set and the English keys of hidden rows; `NotchcastIslandPins` there holds the pinned values; it needs `SettingsTab`, so `notchcast/command-harness-sources.sh` adds it to every harness that compiles `SettingsTab.swift`. On rebase retain the filtering hooks and forced-off getters, even if upstream adds stored defaults or backup restore paths.

- Extensions: `AppSettings.extensionsEnabled` always reads false and ignores writes, including persisted consent and backup restore. `SettingsTab` omits its sidebar row and rejects its settings slug; `SettingsSearchCatalog` omits its search entries. Upstream's `ExtensionManager` publishes no launcher entries while off; `HotKeyManager` exposes no bound extension commands, so a stored binding never registers its chord. `ExtensionCoordinator` rejects store-install links as well as its existing command and link gates. With no entries, upstream's launcher, actions menu and palette accessory have nothing to act on, so they carry no gate.
- Appearance: stock colours resolve from `NSAppearance`, so Light or System would put black text on the black island. `AppSettings.appearance` always reads dark and ignores writes, persisted values, backup restore and the `settings.json` mirror; `AppCore.applyAppearance()` therefore sets `NSApp.appearance` to dark from launch.
- Dragging and snapping: `AppSettings.paletteDraggable` always reads false. Snapping and drop guides run only inside a drag session, so no drag means no snapping; there is no snapping setting of its own.
- Placement: `AppSettings.openOnCursorScreen` always reads true, the stock default, and `palettePosition(on:)` returns nil, so a stored panel position from an earlier build is never restored and the island keeps the notch.
- Language: the app is English only. `AppSettings.pinLanguage()` writes `[NotchcastHidden.language]` to `AppleLanguages` at every launch, and `AppSettings.language` reads `.english` and drops writes, so a language carried in by a settings backup or `settings.json` changes nothing and offers no relaunch; the picker row is hidden like the rows below. Upstream's catalogs and translations stay; `Notchcast.xcstrings` carries English only (`fork-strings.md`). Dictation and Quick Action languages are separate settings and stay.
- Hidden rows: the four General rows end in `.notchcastHidden()`, which renders nothing, and `NotchcastHidden.rows` drops their search entries by English key, because titles are localized; the filter applies to the General tab only, so Dictation's own Language row stays searchable.
- iCloud Sync (#910): our builds carry no iCloud entitlement, so CloudKit never starts; upstream's switch could still be turned on, and then disabled itself while on. `AppSettings.iCloudSyncEnabled` always reads false and ignores writes, so `CloudSyncCoordinator` never starts a session (backups and `settings.json` never carried it). `ICloudSyncOffMigration` clears a switch an earlier build stored. The tab leaves the sidebar, its slug and search like Extensions. Never add the iCloud entitlement to unhide it. The `icloud-sync-off` app proof fails if a stored switch reads on or the engine starts.
- Apple Shortcuts: `AppSettings.appleShortcutsEnabled` always reads false and ignores writes, persisted values, backup restore and the `settings.json` mirror, so `AppleShortcutCoordinator` lists no shortcut in the launcher and never runs the Shortcuts tool; `HotKeyManager.boundAppleShortcutIDs` is empty, so a stored binding registers no chord. The tab leaves the sidebar, its slug and search like Extensions.
- Footer app menu (#882): `RootPaletteView.appMenuButton` ends in `.notchcastHidden()`, so the footer's left side holds only the update pill (and an extension toast); the right-hand action group keeps its trailing place, since the left group already fills the leading width. Only that button opens the `.app` menu, so its entries go with it; each stays reachable elsewhere: version in Settings › About, Check for Updates, About, Support, Settings and Quit as launcher commands, Settings ⌘, and Quit ⌘Q also from the pill's right-click menu, and ⌘, in the palette. Changelog has no other home and goes. `Tests/nc-Notchcast-footer-menu-hidden-test.swift` fails if the button returns.
- Still visible, as in stock: Backup and About (Advanced group, with Support under About's Links), all reachable by slug and in search.
- Menu-bar items: the island replaces all three. `AppSettings.showInMenuBar` and `notesShowsInMenuBar` always read false and `calendarMenuBarDisplay` always reads `.disabled`, all ignoring writes, persisted values, backup restore and the `settings.json` mirror, so `TinycastApp` inserts neither `MenuBarExtra` and `NotesCoordinator` creates no status item. Their key mappings stay. The seven rows end in `.notchcastHidden()` and `NotchcastHidden.rows` drops their search entries; the Raycast import list filters out the `menuBarVisibility` option.
- Calendar › Days to Show stays visible: `calendarSpan` narrows the EventKit fetch for My Schedule and launcher search too. Its section is titled "My Schedule".
- Only the menu-bar icon is gone, not its commands: `TinycastApp`'s `.commands` still declare Settings… ⌘, and Close Window ⌘Q on a scene that is never inserted. Quit and Settings stay reachable from the pill's right-click menu (which also takes ⌘, and ⌘Q), and the launcher.

## Harnesses

`HIDDEN_TESTS` in `notchcast/config.env` lists the upstream harnesses whose whole subject is a hidden item. `notchcast/test-harnesses.sh` drops them from every whole-suite run (PR and Main harnesses CI, Sync, `land.sh`, local `./Scripts/run-tests.sh`) and `notchcast/changed-harnesses.sh` never selects them; naming one still runs it (`./Scripts/run-tests.sh ExtensionTests`). The files stay in `Tests/` and in upstream's `Scripts/run-tests.sh`, so sync is untouched. A harness that also covers visible code (`CalendarTests`, `PalettePlacementTests`, `AppearanceTests`, `InterfaceSizeTests`, and `LanguageTests`, which guards the English plurals, labels and app-name override) keeps running.

- Extensions: `ExtensionTests` (with `ExtensionFetchTests` and `ExtensionTests+MenuBar` compiled into it), `ExtensionAccessoryTests`, `ExtensionCleanupTests`, `ExtensionFormTests` (with `ExtensionListKeyTests`), `ExtensionIconTests`, `ExtensionImageSizeTests`, `ExtensionMetadataTests`, `ExtensionRefreshTests`, `ExtensionSignInTests`, `ExtensionStoreTests`, `ExtensionVersionTests`, and `SymbolsTests` (the SF Symbol catalog only the extension appearance picker reads).
- Apple Shortcuts: `AppleShortcutTests`.
- iCloud Sync: `CloudSyncTests`.

CI steps that served only a hidden item are gone too (#945): CodeQL's JavaScript scan skips the Raycast runtime (`Scripts/raycast-runtime/`, `Tinycast/Resources/RaycastRuntime.generated.js`, `Tests/ext-fixtures/`), the Generated workflow sets up no Node and never rebuilds that runtime (it stays upstream's), and `land.sh` no longer reruns harnesses when `main` moved only in it, since only `ExtensionTests` loads it. Measured on GitHub Actions: CodeQL's JavaScript job fell from 73 s (average of the 10 main runs before) to 58 s, about 15 s of a Linux runner per push to `main`, and Generated saves its Node setup, about 1 s per run; the PR and Main harness lanes already ran no hidden harness, so they are unchanged.

Kept on purpose: everything that guards the hiding (`notchcast-hidden-features-test`, `nc-Notchcast-footer-menu-hidden-test`, `notchcast-icloud-sync-off-migration-test`, the `hidden-settings` and `icloud-sync-off` app proofs); harnesses that only compile a hidden model as a dependency of a visible one (`DeepLinkTests`, `InterfaceSizeTests`, the `$SYNC` sources in `NotesTests` and `SnippetsTests`) and `RaycastTests` (the visible Raycast import); Light-appearance checks inside visible harnesses (`nc-NotchLook-tokens-test`, `nc-Island-keyline-test`, `nc-Notchcast-island-cards-test`) and the DEBUG `keyline` scene, which run with the visible code they sit in and run on no CI runner (scenes) or cost no measurable time; upstream's `Scripts/check-localizations.js` in `Scripts/lint.sh` (0.15 s; dropping it means patching upstream's lint script); and the Debug build, which still compiles hidden code so a rebase keeps it.

When you hide an item, add the harnesses that test only it; when you unhide one, remove them.

Excluded harnesses are no longer compiled in our runs, so un-hiding a feature means fixing its harnesses first.
