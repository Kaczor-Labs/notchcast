# Cleaner

Cleaner scans the current user's app caches, logs, container caches, browser caches and old browser versions, Mail downloads, Homebrew logs, and saved app state. The Cleaner switch sits in Mac Tweaks. Its Clean Up Mac command opens the review in the palette and starts a scan; closing the screen cancels the scan, and Command-R scans again. The same command is Low Disk's Clean Up offer while space is low. Test harnesses inject a filesystem, a Full Disk Access check and any Trash action.

## Invariants

- A scan offers only direct children of each area root, never the root itself: `~/Library/Caches`, `~/Library/Logs`, `~/Library/Saved Application State`, both Mail Downloads folders, each app container's `Data/Library/Logs`, `Data/Library/Caches` and `Data/tmp`, each group container's `Library/Caches`, the browser cache folders in `CleanerUserAreas.swift`, and the old framework versions inside Chrome, Edge and Brave. Diagnostic report and Homebrew log areas offer single files at any depth on the root's volume. Apple and Notchcast items stay out of the list, and protected data never enters the selection. No-access scans stop before reading the filesystem.
- Saved app state older than 31 days and browser framework versions older than the one `Current` points to are listed unticked. Mail Downloads rows are always held back. Rows of every other area are pre-ticked when nothing holds them back.
- A complete, readable scan is required for a row to be ticked. Recent writes, running apps (by name, bundle id or maker, such as `jetbrains` or `jetbrains.com` for IntelliJ), a program running from inside the row, a script runner (Node.js, Deno, Bun, Python, Ruby, Perl) whose working folder or named script, relative or through a link, lies inside it, a repository inside (`.git`, `.hg`, `.svn`, `.jj`, `.pijul`, `_darcs`, in any letter case), protected data, unreadable trees and unsafe paths hold a row back. Outside `~/Library/Caches`, a file held open holds the row back at the scan too.
- The row and every folder above it must be real folders or files. A link or special file inside the row is recorded and not followed, since a move to the Trash never follows it.
- Review keeps selection separate from the highlighted row and from search. The footer counts all selected items and how many the filter hides. When selected items are hidden, Show Selected Items clears the filter and preserves the checks so all selected rows can be reviewed before Move to Trash.
- The runner rechecks the parent folders and the whole selected tree before asking macOS to move a row to the Trash, and skips a row a process this account can inspect runs from or holds open. That reading of processes is reused for one second and the walk after it can take two more, so a file opened in those three seconds can still move while open; its process keeps writing to it in the Trash.
- After the move, the runner compares the item macOS reports in the Trash with the scanned identity; a mismatch is reported as unverified, not as trashed. A failed move keeps its `CocoaError` code. Each selected row gets its own outcome, and one failure leaves the remaining rows eligible.
- The Empty Trash offer is a separate destructive question, answered Empty Trash or Not Now, shown only after a move succeeds, while its setting is on and when no move in the batch ended unverified. A held Return or Enter cannot answer it. Confirming runs the stock Empty Trash action. Not Now leaves the moved items in the Trash. The result keeps missing, skipped, failed and unverified items distinct and shows the move result alongside any Trash result from Finder; a batch with an unverified move says to check the Trash instead. The reported size describes the items moved.
