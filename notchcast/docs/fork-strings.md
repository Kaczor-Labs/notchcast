# Fork localization

## App name

The app reads "Notchcast" without editing upstream's Swift or catalogs. The Tinycast target's last build phase, `Notchcast name override` (`project.yml`), runs `notchcast/name-override.py` after resources are copied and before signing. In every `*.lproj` table and in the built `Info.plist` it replaces "Tinycast" with "Notchcast" in values, never in keys, so `TinycastURLScheme`, `.tinycast` and `com.tinycast.*` identifiers stay. Xcode leaves an English value out of the compiled table when it equals its key, so the phase also writes each such key from `Localizable` and `InfoPlist` (the script's `CATALOGS`) into the `en` table with its renamed text. It prints `name-override: N entries renamed Tinycast -> Notchcast (<per language>)`.

The build fails when a shipped table or `Info.plist` still says Tinycast outside `ALLOWLIST`, when a key-only string of any catalog is missing its renamed `en` entry, or when nothing was renamed. `ci-build.sh` runs `name-override.py --verify` on the built app, which fails if the phase did not run. The allowlist holds the two credits to upstream: "Support Tinycast" (opens upstream's sponsor page) and "Join the Tinycast community" (upstream's Discord, in About). A new catalog joins `CATALOGS` and the phase's `inputFiles`. Swift literals outside the catalogs are kept upstream's unless a user sees them: the three that do are edited in place (the backup file name in `BackupActions.swift`, the quicklinks export name in `QuicklinkCoordinator.swift`, the OAuth `client_name` in `MCPOAuthRequest.swift`). The Dictation helper is signed when it is embedded, before the phase runs, so its name is set at the source: `DICTATION_EXECUTABLE_NAME` in `project.yml` ("Notchcast Dictation", "Notchcast Dev Dictation" in Debug), matched by the launch path in `DictationWorker.swift` and by `Scripts/verify-signature.sh`; `--verify` fails when a path under `Contents/Helpers`, or a helper `Info.plist` name (`CFBundleName`, `CFBundleDisplayName`, `CFBundleExecutable`), says Tinycast in any case; helper identifiers may keep `com.tinycast.*`. `python3 notchcast/name-override-test.py` checks the script on a fake bundle.

The phase edits files that other build steps produced, so Xcode redoes those copies and the phase on every build, even with nothing changed. The built `Info.plist` is a declared input, so the phase always runs after Xcode writes it; without that input Xcode writes `Info.plist` after the phase and the rename is lost.

## Fork table

Fork-only keys live in `Tinycast/Resources/Notchcast.xcstrings`. Use explicit `table: "Notchcast"` on `String(localized:)` and `LocalizedStringResource`, and `tableName: "Notchcast"` on `Text`. Implicit resource literals must become explicit resources. Shared upstream keys keep their original table. The table is English only: it carries no translations, the app pins its language to English (`NotchcastHidden.language`), and the gates reject any non-English localization. Upstream's own tables keep their eight translations. Entries marked `shouldTranslate: false` remain nontranslatable.

Run `python3 notchcast/move-fork-strings.py --fetch` against the intended upstream baseline. It validates everything before writing, restores the upstream catalog byte for byte, and refuses changed shared translations, conflicting entries and unknown literal contexts. `--check` writes nothing and fails if any changes are pending. Drop the separate migration-result commit and rerun the tooling after the feature train lands. Fetching uses the upstream URL and never changes remote configuration.

The installed Swift compiler's `-emit-localized-strings` probe extracted explicit Text, String and resource calls into `Notchcast`. A wrapper taking `LocalizedStringKey` extracted its caller literal into `Localizable`, despite selecting a different table inside the wrapper. Explicit arguments are therefore required. The project recursively includes resources; regenerate with XcodeGen without committing generated files.

Use `bash notchcast/sync-strings.sh` for compiler extraction and synchronization of both tables. `python3 notchcast/check-fork-strings.py` rejects fork keys in Localizable, missing explicit-table keys, non-English localizations and unconverted literals; `check-localizations.js` runs upstream's checker on the fork table with its language list emptied. PR catalog checks invoke it after migration. `xcstrings-union.py --git --catalog Tinycast/Resources/Notchcast.xcstrings` handles fork-table conflicts, including creation on one side. Catalog-order checks allow the initial migration's upstream order restoration and require ordinary relative ordering thereafter.
