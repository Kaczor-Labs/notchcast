# Door: Transcription

**Transcription** goes through stock Dictation: `try await context.transcribe(audioURL)` returns the text of an audio file in the user's own Dictation model and language, decoded and recognized off-main, or throws `NotchcastTranscribeError` (`unavailable`, `busy`, `unreadableAudio`, `failed(message)`). It refuses with `.busy` while the user is dictating (recording or still transcribing) and while another add-on's transcription runs; it never queues behind or interrupts the user. When the user starts dictating mid-run, stock Dictation signals the core directly and waits, before its microphone opens, until the add-on's model call is cancelled and cleaned up, so the user's dictation is never refused busy; the add-on gets `.busy`, also when that dictation already ended, and no further piece of its audio enters the model. A cancelled caller gets `CancellationError`, never the text or `.busy`. `NotchcastCore` injects the one hook (`NotchcastTranscribing`, implemented by `NotchcastDictationBridge`), so no add-on and no Core file names a Dictation type; harnesses pass a fake (`Tests/NotchcastDictationFixture.swift`).
