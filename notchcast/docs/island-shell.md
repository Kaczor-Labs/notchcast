# Island shell

The shell keeps the stock `PalettePanel`, content view, first responder and palette-sized frame. Stock `show()` and key regain use the island's level through two one-line hooks. Paste-target capture, input-source sessions, focus restoration, `hide()` and cleanup execute unchanged. A separate non-activating backdrop paints an opaque black engine outline and never becomes key. Native window coordinates remain authoritative for menus, field editors, cursor rectangles, share anchors and placement readers; no content-rectangle adapter is needed.

`AppCore` owns `IslandCoordinator`. It keeps one backdrop per `CGDirectDisplayID`, shows the rest pill on the primary screen and opens on the pointer screen. A visible palette retains its display across mode changes and re-centers when that display's frame changes. Notch or backing-scale changes recreate the engine surface when no palette or overlays are visible; otherwise recreation waits for their dismissal. Persisted stock placement is ignored. The backdrop is above the menu bar and the palette immediately above it. Summon and key regain write the island level synchronously. While stock sinks the palette for a modal picker, or while a visible palette sits below the island level, the backdrop hides. Modal completion lifts a palette left open through the picker back to the island level, and the rest backdrop returns after a suspended close and modal completion. The base stack pins dragging off and hides placement settings, so drop guides stay off. Compact mode uses the expanded engine state at the native compact panel size, including its stock rendering outset. On a full-screen Space the rest pill, the meeting countdown and status stay off; a notice, a volume level, the meeting expansion, the palette or an overlay still shows, and the backdrop hides once the pill settles back. A display counts as full-screen when one of its on-screen display-wide windows shares its left edge, width and bottom edge with a window of the same app that reports `AXFullScreen`; the top edge moves with the menu bar's reveal strip. AX lists no window from another Space. The AX reads run off the main actor with a 0.25 s timeout each, on every Space change and app activation, and only the latest check applies. Window bounds alone also match a zoomed window. With no Accessibility grant, or on any AX error, the rest pill stays. Scene `full-screen` checks each state with the flag set; scene `full-screen-space` checks on the test display that a zoomed window keeps the rest pill, that a real full-screen Space hides it (kept without a grant), that a notice shows on it, that the pill settles back, and that it returns on the desktop beside a zoomed window of the same app. Not verified: a hung app, and a second display.

The engine receives fixed native sizes rather than SwiftUI content. Palette content mounts once in its stock panel, with root glass disabled and lagoon accent tint applied at the root. Stage width follows native resizing through `IslandSurface.resize`. The outline radius stays 26 points at interface scales 1, 1.1 and 1.2; content and stock internal metrics scale normally. The 1100 by 860 point host fits the 900-point-wide scale-1.2 panel. A notched screen profile derives its sensor width from the auxiliary menu-bar areas and its height from the top safe-area inset; live notch behavior remains unverified.

Mode re-show uses the same synchronous level hook. There is no level KVO or corrective origin write; the only deferred level write is the modal-completion lift. Palette, reports and questions use named levels 26, 27 and 28 respectively. Rest clicks also check palette visibility across all displays. Key-window notifications during a modal schedule one default-mode callback to refresh backdrop visibility after the nested modal loop ends, including when the palette has already closed. System accessibility-display notifications update Reduce Motion, and palette/settings observation updates the app's animation preference.

One engine frame callback paints the native alpha-backed outline and updates the panel content layer mask in one Core Animation transaction. Move and resize notifications update the target synchronously. WindowServer uses the painted alpha for click routing, while AppKit hit testing checks the current engine outline at event time. There is no periodic timer, pointer polling or event-routing toggle. Engine callbacks stop after settling; typing does not remeasure or animate the island.

## Deltas against docs/ui.md

Upstream `docs/ui.md` stays unedited apart from one pointer here, so upstream syncs do not conflict on it. Where it disagrees, this list wins:

- Surface: the palette sits over an opaque black island backdrop instead of a scrim over behind-window blur. The fork pins AppKit appearance to Dark; Light token branches remain upstream reference values and do not drive island rendering.
- Glass: the palette root uses `.identity` glass; regular root glass exists only in the Debug stock latency control. Shared `PopoverMenu` surfaces, dialog roots and both HUD roots use opaque `NotchTheme.Colors.islandSurface`. The action capsule and menu circle keep `frosted(in:)` glass, and dialog buttons stay matte.
- Edge and shadow: the engine outline, not the root clip, owns the island edge. `RootPaletteView` keeps its stock clip but drops its scrim on the island (`paletteOnIsland` also strips the compact bar's capsule glass, button glass and scrim; the stock control keeps both); the backdrop and the palette layer mask share one engine frame callback. The outline radius stays `Theme.Radius.panel` at every interface scale and the palette shadow is suppressed.
- Placement: the palette sits at the display's top centre rather than 8% above centre. Questions sit at the island top on the visible palette's display, otherwise the cursor display; message reports stack below question and palette on the presenter's screen. A volume level draws in the resting pill, or in the report slot under the palette or a question.
- Levels: backdrop main-menu + 1, palette + 2, reports + 3, questions + 4, replacing upstream's `.palette` and `.dialog`.
- Menus: native `MenuPanel` child windows with their stock anchors, keyboard routing and fixed widths; only the content surface turns black. Extension menus keep their feature-owned styling.
- Radius: `row 18`, `menuRow 18`, `keyCap 10`.
- Size: `bottomBarHeight 44`, `resultRowIcon 28` (so the palette result slot is 28pt), `keyCap 22`; `Theme.Typography.headerIconSize 22`, keycap font `.body` medium.
- Dark colours: `selection` white 0.24, `rowHover` white 0.08, `menuHover` white 0.24, `separator` white 0.16; light branches stay upstream's. `primaryAction` (and `progress`) is lagoon `#46f0c6` in dark and `systemBlue` in light.
- Keycaps: `.outline` fills with `NotchTheme.Colors.keyCapFill` (white 0.14) instead of a `border` stroke.
- Island tokens live in `NotchTheme` (`Tinycast/Features/Notchcast/NotchTheme.swift`), not `Theme`: `Spacing.islandInset 16`, `Size.islandRest 96×24`, `Size.islandHost 1100×860`, `Size.islandGlanceWing 140`, `Typography.islandGlanceNSFont` (`.callout` medium with monospaced digits, the AppKit twin of `Theme.Typography.bar`, so a number keeps its width while its digit count holds; the `glance` scene checks the digits. Not built: §3's fixed-width slot, so "in 9 min" to "in 10 min" or "Now" still resizes the pill), `Colors.islandSurface` (black).

## Verification boundary

Debug argument `--island-verify` enters a separate application delegate before migrations, normal scenes or `AppCore.start`. It requires a bundle identifier starting `app.notchcast.v2` (one channel per worker, such as `.v2shell` or `.v2pill`; no "tinycast", which the name override rejects in a helper) and a test display, pins AppKit appearance to dark and bypasses normal startup services. A nine-second independent watchdog exits with code 124. Failed expectations print to stderr and exit with code 1. The stock command-Escape event tap is disabled for this Debug argument, so making the native panel key cannot request a global event-listening grant. The caller also uses a restricted sandbox denying network and Apple Events, with writes limited to scratch and the isolated app channel.

Live checks run only through scratch `vdisplay with -- <command>`, one wrapper at a time; this form works on both Macs. Inside the session the command exports `ISLAND_TEST_DISPLAY` as the `display id` that `vdisplay status` prints, because vdisplay names the screen differently per Mac. `IslandVerification.testScreen` is the one Debug matcher: it accepts only that display, and never the main or built-in one. Without a match, verify mode refuses to run and the island coordinator lists no screen. `AppWindowController`, through `IslandVerification.keepOnTestDisplay`, ends a verify run before it creates or raises any window, re-raises included, when no test display matches, so losing the display after startup fails the run rather than putting a window on a physical screen; the `window-guard-new` and `window-guard-raise` scenes drop the display mid-run and must exit 1 on that check, and `window-guard-deferred` drops it after Settings shows with no further show, so only the raise's queued re-raise can hit the check. A guard scene that gets past the check exits 2, so exit 1 always means the guard fired. Normal Debug and Release are unaffected. A wrapper lock exit of 3 requires waiting and retrying. A physical-screen blackout or failed restoration stops live work. Neither display capture nor Screen Recording permission is used.

At several engine callbacks the proof records both AppKit window frames and both transformed outline bounds, renders each window's own layer tree into a separate bitmap, then composites those bitmaps at their real frames over diagnostic gray. Separate buffers preserve transparency because `CALayer.render(in:)` clears its destination. This proves layer state, not WindowServer composition or presentation latency. The stack-75 gate at `74531b479` passed with 215 frame samples, maximum coordinate disagreement 2.2737367544323206e-13 points, and inspected composites for rest, open start/middle/end, compact, expand, scale-1.2 resize middle and close middle. Later stock-lifecycle scene captures also check the native panel top against the screen top. `IslandController.capture` is async and returns only after the still is taken, so a scene cannot change the pill between asking for a still and its frame.

The fix-round repeat on rebased `7bd152eaa` recorded 220 samples with the same maximum coordinate disagreement, but with synchronous layer capture on, its first changing outline arrived at 121.659 ms versus stack-75's 64.707 ms. A capture-off rerun (timestamps only, three alternating runs per side, one wrapper) settled it: median first post-open callback / first changing outline 17.463 / 44.069 ms at `2c6faabe8` versus 15.931 / 41.882 ms at `74531b479`, +2.2 ms, under one 75 Hz frame, so the fix round did not delay the open; the capture pause caused the earlier gap. This measures main-thread callback and layer state, not WindowServer presentation. Frame logs are in the worker's scratch `timing/` directory.

The unchanged keyboard harness passed live under the wrapper: `PASS: palette keyboard contract (122 checks)`. `Tests/nc-Island-layout-test.swift` compiles the shipped pure geometry source and checks screen/notch/scale anchoring and flipped/native coordinate transforms. `Tests/nc-Island-screens-test.swift` checks explicit display selection, stable retention across reorder and disconnected-display fallback. The fork stack supplies the engine pin, look tokens, dark/drag pins and unchanged keyboard harness. Upstream harnesses also run locally.

Capture, scene, latency, sample collection and CPU timing implementations compile only in Debug. Release retains trivial disabled-entry stubs. A Release compile and demangled symbol scan check that verification implementations and per-frame measurement storage do not ship.

Latency uses the prototype protocol: five alternating stock/island runs, 60 insert/delete events each after warmup, actual local app-index rows, and a clock from in-process `NSEvent` delivery through the updated root body, native layout/display and `CATransaction.flush`. This is CPU input-to-frame-submission latency, not input-to-photon latency. The final measurement at `8cb325a08`, before the later naming rebase and this fix round, was stock median 28.592 ms / p90 40.445 ms and island median 29.073 ms / p90 40.290 ms (300 samples each, 226 indexed apps). The 0.481 ms median difference is smaller than run-to-run variation; this does not establish a regression. Callback intervals were median 16.676 ms / p90 17.276 ms, despite the test mode reporting 75 Hz. Whole-process CPU accumulated during callbacks was median 2.012 ms / p90 3.218 ms, including concurrent process work rather than exclusive engine CPU. Callback interval and CPU samples exclude PNG capture. There were zero engine animation callbacks during all five timed typing sequences. The control uses the same instrumented Debug binary with island placement disabled and native root glass restored, rather than a pristine upstream binary. These numbers are historical measurements, not a fresh benchmark of this fix round. Native keyboard scenes cover typing, arrows, Enter, Escape through the stack then close, Tab and form focus; menu scenes cover Command-K.

## Questions and reports

Native dialog and HUD panels retain their stock presenters, sizing, responders, continuations, fades and dwell tasks. A question uses the visible palette's display or otherwise the cursor display. A message report honors its presenter's supplied screen, even if a different display was active previously. Reports stack below the question and palette on their own display, at a lower level than questions. The backdrop grows to contain these native frames. Native `orderOut` hooks release their reserved frames synchronously, including fade completion; `willClose` also removes entries. `IslandOverlayLayout` receives Theme spacing as injected geometry parameters. Its harness checks preserved accessory size and non-overlapping placement, including negative screen origins and notch offsets.

The second question still cancels immediately. Live native events exercise volume arrows and Enter, multiline text editing with Return and Command-Return, and Escape cancellation. A progress report replaced by completion retains its HUD panel, never hides the palette and never steals the question's key window. The stock 2.4-second message dwell and `extend()` remain intact. Volume no longer uses a HUD: its commands show an island level through `islandPresenter.showLevel` with a 1.5-second dwell, drawn in the resting pill, or as a band in the report slot while the palette or a question is up (see Presentation API). `VolumeHUDController` and its view stay in the tree, hidden and unreferenced, so upstream edits to them never conflict. Dialog and message surfaces, and the unreferenced volume view, use `NotchTheme.Colors.islandSurface`; their content and tone decoration remain. Only a settled rest pill can open the launcher. Expanded backdrop margins cannot switch modes or cancel a question. The backdrop sets `hidesOnDeactivate = false`.

The engine from the stack is `eafeac8`. Repeating the layer/frame proof after its deferred display-link visibility change produced 194 samples with maximum disagreement 2.2737367544323206e-13 points. The first post-open callback moved from 22.38 to 22.93 ms; first changing outline moved from 103.68 to 103.20 ms. Both logs include capture-induced main-thread pauses. No added missing or late opening frame was observed in the layer samples, and the first backdrop still contained the rest pill. These checks do not establish WindowServer presentation.

## Pill menu and glance

A primary click still opens the launcher and never the menu. Rows come from `PillMenuRow.sections` in `Features/Island/Model/PillMenuRows.swift`: Join and Open in Calendar while a meeting is carded, then My Schedule, Clipboard History and the Notes commands as their features allow, then Check for Updates, Support and Settings, then Quit. `IslandCalendarGlance` follows `CalendarCoordinator.cardedMeeting`. ## Screen capture

Settings' Notchcast pane has "Show in screenshots and videos" (`AppSettings.islandShowsInCaptures`, settings file `appearance.islandShowsInCaptures`, on by default). `IslandCoordinator.applyCaptureSharing` sets every backdrop's `sharingType` to `.readOnly` when on and `.none` when off, on each rebuild and live through its own observation of the setting, started with the island (so scenes run the shipped path); `IslandPillMenu` carries it to the menu panel it observes, open or next opened. Once a window is set to `.none`, AppKit's `sharingType` getter keeps returning `.none` (seen on Darwin 27.2) while WindowServer does take `.readOnly` again, so check WindowServer's `kCGWindowSharingState`, never the getter. So a window that has been shown again is hidden by replacing it, and turning the setting off closes what would keep it: the pill menu, if its panel or any backdrop was shown again while it stayed open, and the launcher, if a backdrop must be replaced; a closing menu stays capturable for its fade-out. The palette, questions, reports and every other stock panel stay capturable: they are stock surfaces the island places, not the island. Scene `capture-sharing` (`IslandCaptureScenes.swift`) reads `kCGWindowSharingState` on every visible backdrop and the open pill menu at the default, after turning it off with the menu open, after reopening the menu, after turning it back on with the menu open, after turning it off again with that menu open (the menu must close and every window be replaced), and with the menu closed. Not verified: a real screenshot or recording, because the agent shell has no Screen Recording permission.

## Presentation API

Code outside `Features/Island/` reaches the island only through `AppCore.islandPresenter`, an `any IslandPresenting` (`Service/IslandPresenting.swift`) that add-on coordinators take in their init. Its values (`IslandLevel`, `IslandNotice`, `IslandStatus`, `IslandMenuRow`) are Foundation-only in `Model/IslandPresentation.swift`. `showLevel` is the one generic level call for every source: Tinycast volume now, add-ons later (hardware volume keys, brightness, keyboard backlight). `IslandLevel.source` is the caller's own parameter, and nothing in the presenter or its types is volume-specific. The shipped `IslandPresenter` renders levels, notices and status on the resting pill, in the same order as the accessibility value: a level, else a notice, else the meeting glance, else the status glyphs. `setMenuRows` adds rows to the pill menu, in one section between the feature rows and Updates, Support, Settings and Quit: owners in their first registration's order, which a replacement keeps, rows in array order, an empty array removing the owner. The title is the caller's and never localized; the menu filter and keys apply to it, and choosing it closes the menu before `onSelect` gets its id. Each row gets a check column, filled when `isChecked` is true and empty otherwise, so it lines up with the stock rows' icons. Rows set while the menu is open refit it, and the keyboard cursor stays on its row, known by owner and id rather than title, or on its index when that row is gone. The DEBUG scene `pill-menu-rows` (`Service/IslandMenuRowScenes.swift`) checks order, replacement in place, the cursor kept, removal, filtering and selection on the test display. `IslandNoticeArt` (`Service/IslandNoticeArt.swift`) draws a notice as a still progress ring (no spinner) or its symbol, tinted `Theme.Colors.destructive` when `isFailure` is set, then its text in `islandGlanceNSFont`, truncated to the glance wings; on a notch the text sits right of it. `IslandStatusArt` draws the status glyphs in a row, each with at most four characters of its `text`, centred and never narrower than the rest pill, or right of a notch; when the row is wider than its wing it drops the oldest statuses first, so the newest, which the pill's tap acts on, always shows, and the accessibility value still lists every label. Notices stack in `IslandNoticeQueue` (`Model/`), newest on top: the pill shows only the top one, and only its dwell runs, for `IslandNotice.dwell`: the poster's `seconds`, or by default the stock message HUD's 2.4 s, and 4 s for a failure (design system §10), while a progress notice stays until its caller ends it. Whatever keeps it unseen pauses that dwell: a level (in the pill or as a band), the palette or a question over the pill, or no resting pill at all (no display); it resumes with what it had left once the notice is seen again. The presenter observes the palette and question while a notice is live, and every rebuild calls `restingChanged()`. When the top notice expires or is ended, the one under it returns with the dwell it had left; ending a covered notice drops it without touching the top, and reposting an id keeps its place in the stack and restarts its dwell. `Tests/nc-Island-notice-test.swift` checks these rules and the announcements (model proof), with the 4 s failure default. The DEBUG scene `notice-unseen` (`Service/IslandNoticeScenes.swift`) posts a 0.6 s notice under the open launcher and another with no display, waits 1 s, and requires each to show once the launcher closes or the display returns, then run out its dwell (rendering proof). A notice also holds back the meeting expansion, which starts when the notice ends if the window is still open, and a notice posted mid-expansion cuts it short, as a level does. The island window's canvas is one accessibility group labelled "Notchcast" whose value is what the island shows now, in presenter order: the level as "<label>, <percent>", else empty while the palette covers the pill, else the notice text, else the meeting glance as "<title>, <countdown>", else the status labels, empty at rest; pressing it is the pill's click. The `onTap` given to `post` and `setStatus` replaces that click on the resting pill: the live notice's tap, else none under the meeting glance, else the last status's tap, else the launcher. The value refreshes on every `frameChanged`, so it hides when the palette opens and returns when it closes without a new announcement. A notice is announced once per id and text when it first reaches the top, so a progress repost and a notice returning from under a newer one stay quiet; levels and status only change the value. The DEBUG scene `island-ax` (`Service/IslandAccessibilityScenes.swift`) hit-tests the pill through in-process AX and checks role, label and value at rest, status, glance, notice and level, and counts announcements through `IslandVerification.announcements`; it also unplugs and replugs the display and requires the old pill cleared, the new resting pill carrying notice and status, and no new announcement, because every rebuild hands them over through `IslandPresenter.restore` without posting; when VoiceOver, Switch Control or Accessibility Inspector runs it prints `NOT VERIFIED: other AX client` and skips the reads. A level shows in the resting pill on the island's screen, or as a band in the report slot while the palette or a question is up. `IslandLevelDwell` (`Model/`) keeps it 1.5 s past the last call, so a burst of repeats is one presentation, and its `placement(palette:question:)` picks pill or band. The presenter observes `palette.isVisible` and `isShowingDialog` while a level is live, so opening or closing either mid-dwell moves the level between pill and band without a new presentation or a restarted dwell. `Tests/nc-Island-level-test.swift` checks those rules and the outlined zones past 0...1 (model proof). The DEBUG scenes `volume`, `volume-palette` and `volume-palette-open` (`Service/IslandVolumeScenes.swift`) check pill, band and the mid-dwell move live on the test display (rendering proof). `Tests/nc-Island-presenter-test.swift` holds `RecordingIslandPresenter`, a fake that records each call in order, and checks that it clears status, menu rows and notices.

## Meeting expansion

When Calendar's carded meeting enters its join window, the resting pill grows once to two lines, glyph and title over the grey countdown, for 6 s, then settles back to the glance. `IslandMeetingExpansion` (`Model/`) decides it: once per occurrence, keyed by event id and start, in memory only and pruned to the carded meeting, so a new occurrence of the same event expands again and a relaunch can expand once more. Priority is question > palette > level > notice > expansion > rest > empty. An expansion waits while a level or a notice shows and starts when it ends; a level or notice arriving mid-expansion cuts it short and spends it; a palette or question open at window start spends it, so it never replays when they close. `IslandPresenter` owns it: `IslandCoordinator.showGlance` hands it the glance's occurrence through `meetingChanged`, it runs at most one token-checked expansion task, and it sets `IslandController.expanded`, which the controller draws as the engine's `.expanded` surface at the glance's width or wider. Motion follows the existing path, so Reduce Motion and Show animations apply. `IslandCanvas` cross-fades the glance and the expansion inside a transparency layer, because `NSImage.draw` resets the context alpha; glyphs in the glance and level fades now fade with their art. The backdrop panel lives in `Service/IslandBackdrop.swift`. Clicking the expanded pill does not open the launcher; only the compact rest does.

## Update

`IslandUpdateActivity` (`Service/`), owned and started by `IslandCoordinator`, observes `UpdateCoordinator.stage` and mirrors only the update the user started; an automatic offer (`.available`), `.idle` and `.checking` show nothing. `IslandLiveState` (`Model/`) maps the stage to notice and status, all with id `update`: `.installing` holds one progress notice (`arrow.down.circle`, the installer phase's own "Downloading…" at received over expected, "Expanding…" and "Verifying…" at 1) until the stage leaves installing; `.readyToRelaunch` posts "Update ready" with a 2.4 s dwell and sets the `arrow.clockwise.circle` status, both tapping through to the launcher where the palette's own pill offers Relaunch; `.failed` posts a failure notice "Update failed" with a 4 s dwell, which the presenter's queue runs out and sets the `exclamationmark.arrow.circlepath` status, both tapping `UpdateCoordinator.showFailure` (Try Again); a cancel back to `.available` ends the notice and clears the status. The status is set with the notice, which outranks it, so it shows once the notice ends. All strings are existing catalog ones. `Tests/nc-Island-live-test.swift` checks every stage and that cancel clears both (model proof). The DEBUG scene `update` (`Service/IslandUpdateScenes.swift`) injects stages through `IslandUpdateActivity.preview`, never a download, reads the value through in-process AX at each step, and checks the real 2.4 s ready dwell, that a tap on the ready status opens the palette, that the value is empty under the palette and returns on close without a new announcement, the failed notice then status (dwell shortened to 0.6 s to fit the watchdog), that cancel clears, and that each stage announces once. Its stills `update-download` (ring at 30 % and "Downloading…"), `update-ready` (the ready status glyph) and `update-failed` (the failure notice) show what the pill draws; before the ready tap the scene waits for the pill's spring from notice to status to settle, since a moving pill takes no click. For the failure it sets the real stage through the DEBUG `UpdateCoordinator.previewFailure`, since `showFailure` guards on it, and checks that a tap on the failed status raises the "Update failed" question with Try Again as the default (read through the DEBUG `DialogController.shown`) and that Esc answers OK (the DEBUG `DialogController.lastAnswer` is the cancel index) and closes it with the failure kept; the still `update-try-again` shows that question.

The launch after an install reports on the island, not the stock HUD: `IslandUpdateActivity.report` takes `UpdateCheckStore.takeInstallReport()` from `AppCore` and posts `IslandLiveState(report:)`, a notice with id `update` and no status. The new version running posts "Updated to <version>" (`checkmark.circle`, the fork table's one new string) for the stock HUD's 2.4 s, tapping through to the launcher. A newer recorded install than the running version posts the failure notice "Update failed" for 4 s; its tap asks the stock question with the stock text ("<app> <version> could not be installed. Check for updates to try again.") and a Try Again button, which runs `UpdateCoordinator.checkForUpdates`, the stock check that offers the release in the launcher's pill. `Tests/nc-Island-live-test.swift` checks both notices (model proof). The DEBUG scene `install-report` (`Service/IslandInstallReportScenes.swift`) posts both reports with shortened dwells, checks the installed notice and its dwell, taps the failure notice, requires the "Update failed" question with Try Again as the default (through `DialogController.shown`) and the launcher closed, and answers Esc, which must answer OK and close it with no check started; the stills `install-report-installed`, `install-report-failed` and `install-report-try-again` show each. Not verified: a real relaunch after an install.
