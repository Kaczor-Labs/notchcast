# Island shell

The shell keeps the stock `PalettePanel`, content view, first responder and palette-sized frame. Stock `show()` and key regain use the island's level through two one-line hooks. Paste-target capture, input-source sessions, focus restoration, `hide()` and cleanup execute unchanged. A separate non-activating backdrop paints an opaque black engine outline and never becomes key. Native window coordinates remain authoritative for menus, field editors, cursor rectangles, share anchors and placement readers; no content-rectangle adapter is needed.

`AppCore` owns `IslandCoordinator`. It keeps one backdrop per `CGDirectDisplayID`, shows the rest pill on the primary screen and opens on the pointer screen. A visible palette retains its display across mode changes and re-centers when that display's frame changes. Notch or backing-scale changes recreate the engine surface when no palette or overlays are visible; otherwise recreation waits for their dismissal. Persisted stock placement is ignored. The backdrop is above the menu bar and the palette immediately above it. Summon and key regain write the island level synchronously. While stock sinks the palette for a modal picker, or while a visible palette sits below the island level, the backdrop hides. Modal completion lifts a palette left open through the picker back to the island level, and the rest backdrop returns after a suspended close and modal completion. The base stack pins dragging off and hides placement settings, so drop guides stay off. Compact mode uses the expanded engine state at the native compact panel size, including its stock rendering outset.

The engine receives fixed native sizes rather than SwiftUI content. Palette content mounts once in its stock panel, with root glass disabled and lagoon accent tint applied at the root. Stage width follows native resizing through `IslandSurface.resize`. The outline radius stays 26 points at interface scales 1, 1.1 and 1.2; content and stock internal metrics scale normally. The 1100 by 860 point host fits the 900-point-wide scale-1.2 panel. A notched screen profile derives its sensor width from the auxiliary menu-bar areas and its height from the top safe-area inset; live notch behavior remains unverified.

Mode re-show uses the same synchronous level hook. There is no level KVO or corrective origin write; the only deferred level write is the modal-completion lift. Palette, reports and questions use named levels 26, 27 and 28 respectively. Rest clicks also check palette visibility across all displays. Key-window notifications during a modal schedule one default-mode callback to refresh backdrop visibility after the nested modal loop ends, including when the palette has already closed. System accessibility-display notifications update Reduce Motion, and palette/settings observation updates the app's animation preference.

One engine frame callback paints the native alpha-backed outline and updates the panel content layer mask in one Core Animation transaction. Move and resize notifications update the target synchronously. WindowServer uses the painted alpha for click routing, while AppKit hit testing checks the current engine outline at event time. There is no periodic timer, pointer polling or event-routing toggle. Engine callbacks stop after settling; typing does not remeasure or animate the island.

## Deltas against docs/ui.md

Upstream `docs/ui.md` stays unedited apart from one pointer here, so upstream syncs do not conflict on it. Where it disagrees, this list wins:

- Surface: the palette sits over an opaque black island backdrop instead of a scrim over behind-window blur. The fork pins AppKit appearance to Dark; Light token branches remain upstream reference values and do not drive island rendering.
- Glass: the palette root uses `.identity` glass; regular root glass exists only in the Debug stock latency control. Shared `PopoverMenu` surfaces, dialog roots and both HUD roots use opaque `Theme.Colors.islandSurface`. The action capsule and menu circle keep `frosted(in:)` glass, and dialog buttons stay matte.
- Edge and shadow: the engine outline, not the root clip, owns the island edge. `RootPaletteView` keeps its stock clip and scrim; the backdrop and the palette layer mask share one engine frame callback. The outline radius stays `Theme.Radius.panel` at every interface scale and the palette shadow is suppressed.
- Placement: the palette sits at the display's top centre rather than 8% above centre. Questions sit at the island top on the visible palette's display, otherwise the cursor display; message reports stack below question and palette on the presenter's screen. Volume keeps its stock bottom placement.
- Levels: backdrop main-menu + 1, palette + 2, reports + 3, questions + 4, replacing upstream's `.palette` and `.dialog`.
- Menus: native `MenuPanel` child windows with their stock anchors, keyboard routing and fixed widths; only the content surface turns black. Extension menus keep their feature-owned styling.

## Verification boundary

Debug argument `--island-verify` enters a separate application delegate before migrations, normal scenes or `AppCore.start`. It requires a bundle identifier starting `com.tinycast.app.v2` (one channel per worker, such as `.v2shell` or `.v2pill`) and a test display, pins AppKit appearance to dark and bypasses normal startup services. A nine-second independent watchdog exits with code 124. Failed expectations print to stderr and exit with code 1. The stock command-Escape event tap is disabled for this Debug argument, so making the native panel key cannot request a global event-listening grant. The caller also uses a restricted sandbox denying network and Apple Events, with writes limited to scratch and the isolated app channel.

Live checks run only through scratch `vdisplay with -- <command>`, one wrapper at a time; this form works on both Macs. Inside the session the command exports `ISLAND_TEST_DISPLAY` as the `display id` that `vdisplay status` prints, because vdisplay names the screen differently per Mac. `IslandVerification.testScreen` is the one Debug matcher: it accepts only that display, and never the main or built-in one. Without a match, verify mode refuses to run and the island coordinator lists no screen. `AppWindowController` ends a verify run before it creates or raises any window, re-raises included, when no test display matches, so losing the display after startup fails the run rather than putting a window on a physical screen; the `window-guard-new` and `window-guard-raise` scenes drop the display mid-run and must exit 1 on that check. Normal Debug and Release are unaffected. A wrapper lock exit of 3 requires waiting and retrying. A physical-screen blackout or failed restoration stops live work. Neither display capture nor Screen Recording permission is used.

At several engine callbacks the proof records both AppKit window frames and both transformed outline bounds, renders each window's own layer tree into a separate bitmap, then composites those bitmaps at their real frames over diagnostic gray. Separate buffers preserve transparency because `CALayer.render(in:)` clears its destination. This proves layer state, not WindowServer composition or presentation latency. The stack-75 gate at `74531b479` passed with 215 frame samples, maximum coordinate disagreement 2.2737367544323206e-13 points, and inspected composites for rest, open start/middle/end, compact, expand, scale-1.2 resize middle and close middle. Later stock-lifecycle scene captures also check the native panel top against the screen top.

The fix-round repeat on rebased `7bd152eaa` recorded 220 samples with the same maximum coordinate disagreement, but with synchronous layer capture on, its first changing outline arrived at 121.659 ms versus stack-75's 64.707 ms. A capture-off rerun (timestamps only, three alternating runs per side, one wrapper) settled it: median first post-open callback / first changing outline 17.463 / 44.069 ms at `2c6faabe8` versus 15.931 / 41.882 ms at `74531b479`, +2.2 ms, under one 75 Hz frame, so the fix round did not delay the open; the capture pause caused the earlier gap. This measures main-thread callback and layer state, not WindowServer presentation. Frame logs are in the worker's scratch `timing/` directory.

The unchanged keyboard harness passed live under the wrapper: `PASS: palette keyboard contract (122 checks)`. `Tests/nc-Island-layout-test.swift` compiles the shipped pure geometry source and checks screen/notch/scale anchoring and flipped/native coordinate transforms. `Tests/nc-Island-screens-test.swift` checks explicit display selection, stable retention across reorder and disconnected-display fallback. The fork stack supplies the engine pin, look tokens, dark/drag pins and unchanged keyboard harness. Upstream harnesses also run locally.

Capture, scene, latency, sample collection and CPU timing implementations compile only in Debug. Release retains trivial disabled-entry stubs. A Release compile and demangled symbol scan check that verification implementations and per-frame measurement storage do not ship.

Latency uses the prototype protocol: five alternating stock/island runs, 60 insert/delete events each after warmup, actual local app-index rows, and a clock from in-process `NSEvent` delivery through the updated root body, native layout/display and `CATransaction.flush`. This is CPU input-to-frame-submission latency, not input-to-photon latency. The final measurement at `8cb325a08`, before the later naming rebase and this fix round, was stock median 28.592 ms / p90 40.445 ms and island median 29.073 ms / p90 40.290 ms (300 samples each, 226 indexed apps). The 0.481 ms median difference is smaller than run-to-run variation; this does not establish a regression. Callback intervals were median 16.676 ms / p90 17.276 ms, despite the test mode reporting 75 Hz. Whole-process CPU accumulated during callbacks was median 2.012 ms / p90 3.218 ms, including concurrent process work rather than exclusive engine CPU. Callback interval and CPU samples exclude PNG capture. There were zero engine animation callbacks during all five timed typing sequences. The control uses the same instrumented Debug binary with island placement disabled and native root glass restored, rather than a pristine upstream binary. These numbers are historical measurements, not a fresh benchmark of this fix round. Native keyboard scenes cover typing, arrows, Enter, Escape through the stack then close, Tab and form focus; menu scenes cover Command-K.

`PalettePanel`, `MenuPanel`, all stock feature screens, and stock hide behavior are unchanged. The rejected replacement of `PalettePanel.contentView` by a large island canvas was dropped. Native panel geometry makes its proposed coordinate adapter unnecessary.

Stock placement helpers and `AppCore.shared` hooks remain intentionally to keep upstream rebases small; the two native `orderOut` hooks make overlay teardown independent of occlusion notifications.

Not verified: real key focus without activation, IME and dead keys, VoiceOver, drag and drop, tooltips, outside click, full-screen Spaces, physical notch fusion, real two-screen pointer interaction, WindowServer presentation, and the compositor glass rim over black. Own-layer pictures cannot establish the last two. The Settings activation/deactivation scene could verify the backdrop flag and visibility after a deactivate call, but macOS rejected the agent process's activation request; a real active-to-inactive transition remains unverified.

## Questions and reports

Native dialog and HUD panels retain their stock presenters, sizing, responders, continuations, fades and dwell tasks. A question uses the visible palette's display or otherwise the cursor display. A message report honors its presenter's supplied screen, even if a different display was active previously. Reports stack below the question and palette on their own display, at a lower level than questions. The backdrop grows to contain these native frames. Native `orderOut` hooks release their reserved frames synchronously, including fade completion; `willClose` also removes entries. `IslandOverlayLayout` receives Theme spacing as injected geometry parameters. Its harness checks preserved accessory size and non-overlapping placement, including negative screen origins and notch offsets.

The second question still cancels immediately. Live native events exercise volume arrows and Enter, multiline text editing with Return and Command-Return, and Escape cancellation. A progress report replaced by completion retains its HUD panel, never hides the palette and never steals the question's key window. The stock 2.4-second message dwell and `extend()` remain intact. Volume uses the same `HUDPresenter` with its stock 1.6-second dwell, bottom-screen height-fraction placement and window level; it does not grow the island. Dialog, message and volume surfaces use `Theme.Colors.islandSurface`; their content and tone decoration remain. Only a settled rest pill can open the launcher. Expanded backdrop margins cannot switch modes or cancel a question. The backdrop sets `hidesOnDeactivate = false`.

The engine from the stack is `eafeac8`. Repeating the layer/frame proof after its deferred display-link visibility change produced 194 samples with maximum disagreement 2.2737367544323206e-13 points. The first post-open callback moved from 22.38 to 22.93 ms; first changing outline moved from 103.68 to 103.20 ms. Both logs include capture-induced main-thread pauses. No added missing or late opening frame was observed in the layer samples, and the first backdrop still contained the rest pill. These checks do not establish WindowServer presentation.

## Menus

`MenuPanel` and its controller are unchanged. The shared `PopoverMenu` surface has an opaque black backing; action menus, filter menus and form dropdowns retain their stock content, native child window, keyboard routing and control anchors. Their palette-sized parent frame remains correct. No menu placement adapter or menu controller hook is needed.

Live checks open the real action menu with Command-K and the clipboard type filter with Command-P. Each menu is the key child of the native palette and its frame stays inside that palette. Typing filters action rows; successive Escape events clear the menu query, close the menu and return key focus, then close the palette. Down and Enter select the text filter. Inspected own-layer composites show black menu surfaces inside the island; the native menu shadows and WindowServer composition remain outside the capture proof.

## Pill menu and glance

A secondary click on the resting pill (right, Control or Option click) opens `IslandPillMenu`: the stock `PopoverMenu` in a stock `MenuPanel`, hung with `.belowControl(pill, trailing: false)` off the backdrop. A primary click still opens the launcher and never the menu. Rows come from `PillMenuRow.sections` in `Features/Island/Model/PillMenuRows.swift`: Join and Open in Calendar while a meeting is carded, then My Schedule, Clipboard History and the Notes commands as their features allow, then Check for Updates, Support and Settings, then Quit. The menu is the only Settings and Quit entry once hide-menubar removes the status item, so it handles Command-comma and Command-Q itself. `Theme.Size.pillMenuVisibleRows` lifts `PopoverMenu`'s mid-row cap because the row set is fixed and short. Typing filters through the shared `menuQuery` and refits the panel with `MenuPanelController.update`; Escape clears a query, then closes. The backdrop is never key, so the stock resign path would hide the palette; the menu watches its own panel's `didResignKey` instead.

`IslandCalendarGlance` follows `CalendarCoordinator.cardedMeeting`. While a meeting is carded, the primary rest pill widens by up to `Theme.Size.islandGlanceWing` on each side and shows the provider symbol, the title and a countdown in `Theme.Typography.islandGlanceNSFont`. `IslandGlanceLayout` drops the title before the countdown when the space is too small. A click on a glancing pill opens the launcher; it never joins a meeting. Only the right-click menu's Join row joins.

The Debug scenes `pill-menu`, `pill-settings`, `glance`, `glance-menu`, `pill-menu-quiet` and `pill-settings-quiet` (`IslandPillScenes.swift`) run under the same verification boundary. `glance` and the two `-quiet` scenes send no input: they open the menu through the pill's `onMenu` callback, filter by setting the query, close it by making another own panel key (the menu must close before the stock resign path yields), run the Settings row's action, and read each Settings pane's accessibility text to prove the menu-bar rows are gone, after first querying the app's own windows through AX, because SwiftUI builds no accessibility nodes until an AX client has asked; the others click the pill with synthetic events delivered to the island window in-process, so another app's window over the pill does not intercept them, but they are recorded as input proofs only while no other Notchcast runs. Together they check menu geometry below the pill, rows, filtering, Escape order, Control and Option click, Command-comma, and a Settings window with no status item. The glance scene previews a synthetic Zoom meeting through a Debug-only `IslandCalendarGlance.preview` rather than through `CalendarStore`. `glance-modal` sends no input either: it closes the launcher while a modal hides a carded pill and requires the pill visible once the modal ends. `pill-busy` clicks the pill in-process while the launcher is open and again while it closes, and requires that no menu opens. The `ws-pill`, `ws-menu`, `ws-busy`, `ws-boundary`, `ws-hover`, `ws-glance-menu`, `ws-quit-key` and `ws-quit-row` scenes (`IslandInputScenes.swift`) send real input instead: mouse events go through WindowServer's HID tap at screen points, keys go to the app's own pid only. They need `Scripts/island-input-helper.swift`, built with `swiftc` into scratch and started under the same sandbox before the app with the log path as its argument and in `ISLAND_HELPER_LOG`; it puts an opaque window just below the island's level over the top of the test display and logs each click it receives, and each click WindowServer gives another process, so a click just outside the outline is shown to pass through. `ws-busy` records which window each right-down reaches with the outline at that event: a rest right-click must hit the backdrop inside the outline and open the menu, a mid-close one must hit it the same way and open none, and over the open launcher, where no backdrop point inside the outline is uncovered, the launcher must take the click (`pill-busy` proves the pill's own refusal there); `ws-hover` requires that hovering the pill changes no window. The quit scenes quit the isolated bundle. `Tests/nc-Island-pill-test.swift` covers row sections and glance layout.

Not verified: a real EventKit meeting driving the glance, the glance on a notched screen, and the menu over a full-screen Space.
